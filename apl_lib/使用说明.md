# APL 使用说明

本文是 APL 宿主接入的统一使用入口，与 `apl_lib` 源码一起维护。适用当前 0.3.0 开发版，参数格式 v6、定义修订 7。字段范围与完整约束见[运行时参数配置](../docs/规格/APL运行时参数配置.md)，Excel 模板和产品示例见[参数目录](parameters/README.md)。

宿主需要提供的硬件接口、数据单位、RGB输出、周期和存储要求见[宿主接入要求](宿主接入要求.md)。

## 1. APL 与宿主分别负责什么

APL 负责按键业务、运行状态、自动/恒湿/风干策略、目标风档和转速、显示状态及运行记忆内容。宿主提供传感器、面板和负载驱动，每 1ms 调用一次 `apl_tick_1ms`；APL 内部每 10 次调用推进一个 10ms 业务帧。宿主还负责参数接收、存储、完整性检查和电机实际调速。

首次烧录后可以不导入参数表：用固件内置缺省配置初始化，进入待机，再通过面板或命令开机。已导入完整有效参数时，冷启动加载该表。

## 2. 加入工程

编译以下文件，并加入两个头文件搜索目录：

- 源码：`apl_lib/src/apl.c`、`apl_lib/src/apl_core.c`、`apl_lib/src/apl_hmi.c`、`apl_lib/src/apl_wifi.c`。
- 搜索目录：`apl_lib/include`、`apl_lib/config`。
- 公开入口：`apl.h`。宿主持有 `struct apl` 实例；不要读写其内部占位存储。

`apl_build_config.h`统一定义编译能力，`apl_core_config.h`维护缺省参数和约束，`apl_hmi_config.h`维护面板设置。参数表只能启用已经编译的能力。硬件回调表先整体清零，再填写需要的回调；回调表与上下文在实例使用期间必须一直有效。

## 3. 不导入参数表时的缺省配置

当前工程默认净化和加湿均启用，一档开机，风干一小时、一档风干，传感器异常备用二档；显示轮换 20 秒，定时按键步进 1 小时。辅助模块和传感器按编译能力选配，完整默认值见参数目录。

风机目标转速如下，单位为 rpm：

| 输出档位 | 缺省目标转速 | 固件缺省宏 | 参数字段 |
|---|---:|---|---|
| 睡眠 | 400 | `APL_DEFAULT_FAN_SLEEP_RPM` | `fan_sleep_rpm` |
| 一档 | 600 | `APL_DEFAULT_FAN_GEAR1_RPM` | `fan_gear1_rpm` |
| 二档 | 900 | `APL_DEFAULT_FAN_GEAR2_RPM` | `fan_gear2_rpm` |
| 三档 | 1200 | `APL_DEFAULT_FAN_GEAR3_RPM` | `fan_gear3_rpm` |
| 极速 | 1500 | `APL_DEFAULT_FAN_TURBO_RPM` | `fan_turbo_rpm` |
| 风机关闭 | 0 | 不适用 | 不适用 |

这套转速是本工程的通用起始值，可供未导表启动和仿真使用；产品应按实际电机能力调整。实际电机仍需宿主驱动接入。自动模式先计算最终输出档位，再使用该档 rpm；恒湿、风干和异常备用档同样处理。

优先关系为：**已导入有效参数表 > 固件缺省宏**。宏未被项目覆盖时采用上表数值。项目可修改 `apl_core_config.h`，或在构建配置中定义这些宏，例如 `APL_DEFAULT_FAN_GEAR1_RPM=700`，然后重新编译固件。宏和参数允许 0～65535；显式填 0 表示该档停转，不会被替换成缺省值。

Wi-Fi产品标识字符串`pid`在Studio“运行参数 → Wi-Fi 联网”中填写，最多16位ASCII字母/数字，默认空字符串。宿主通过`apl_core_get_pid(&device.core, pid)`复制读取，缓冲区至少`APL_PRODUCT_PID_MAX + 1u`（17）字节；它随配置存储，不属于运行记忆。`APL_COMPILE_WIFI=0`时PID和联网专用API不声明、不编译，参数存储也移除；宿主按同一宏保护调用。详情见[PID接入](../docs/规格/APL运行时参数配置.md#产品-pid-与宿主接入)。

## 4. 最小宿主接入

下面以轮询目标转速方式说明调用顺序。`host_*` 是宿主驱动函数，由嵌入式工程提供；`core_ops` 中继续填写水位、传感器、泵、UV 等实际回调。

```c
#include "apl.h"
#include <stddef.h>

static struct apl device;
static struct apl_core_ops core_ops;
static struct apl_hmi_ops hmi_ops;

/* 宿主提供：0rpm停止，非0为目标转速。 */
extern void host_motor_set_target_rpm(uint16_t rpm);

enum apl_profile_result product_start(const struct apl_profile *stored_profile)
{
    enum apl_profile_result result;
    /* 首次调用前填写core_ops/hmi_ops；此时物理负载已关闭，尚未启动tick。 */
    result = apl_init_profile(&device, &core_ops, NULL,
                             &hmi_ops, NULL, stored_profile);
    if (APL_PROFILE_OK != result)
    {
        return result; /* 没有完成初始化，宿主处理错误后再决定是否回退。 */
    }
    apl_link_bind(&device);
    /* 需要恢复兼容的运行记忆时，在这里恢复，第一拍前完成。 */
    return APL_PROFILE_OK;
}

void product_tick_1ms(void)
{
    /* 仅在product_start成功后，前台每APL_TICK_MS（1ms）调用一次。 */
    apl_tick_1ms(&device);
    host_motor_set_target_rpm(apl_core_get_fan_target_rpm(&device.core));
}
```

首次没有参数表时调用 `product_start(NULL)`。有表时传入已解码的 `struct apl_profile` 地址。初始化成功后，初始状态是待机；面板按键需要正确实现 `hmi_ops.get_key_state`。只做主控测试时，也可在初始化后调用 `apl_core_power_on(&device.core)`，再推进 tick，缺省一档会给出 600 rpm。

`apl_init` 是原有缺省初始化入口，配置与空表初始化一致。推荐的 1ms 入口按实例独立计数，成功初始化后从 0 开始，第 10 次调用执行首个业务帧。按键采样与输出更新仍为 10ms，自检 2 秒、长按 3 秒和预处理 5 秒均保持不变。目标转速可在每次调用后读取，但首个业务帧前仍是初始化值。

旧 `apl_tick` 仍可每 10ms 调用；只使用主控时可以调用 `apl_core_init_profile`，并每 10ms 推进 `apl_core_tick`；独立人机的 `apl_hmi_tick` 也保持 10ms。对同一实例不要混用新旧入口，也不要同时推进组合对象和其内部主控或人机，否则会重复计时。所有 API、tick 和参数操作在前台或同一任务串行执行；定时中断只记录时间事件，不能直接或重入调用 APL。升级后宿主与库需使用同版本头文件一起重新编译，历史冻结 SDK 保留各自接口。

## 5. 目标转速与负载输出

在 tick 后调用 `apl_core_get_fan_target_rpm`，读取的是已提交输出档位的目标值。快照 `fan_target_rpm` 与它一致。待机和风机关闭时返回 0；恢复运行记忆后，首个 10ms 业务帧提交输出，再返回当前参数对应的转速。

也可以保留 `core_ops.set_fan(on, gear, ctx)` 变化回调，在回调中读取同一个 getter。APL 在回调前已更新输出状态，因此读到的是新目标。宿主不再单独维护档位到 rpm 的映射；测速、PWM 和电机闭环由宿主驱动完成。

上电面板全灯自检 2 秒，随后恢复状态显示；每次开机后传感器预处理 5 秒，三位数码管横段同步向下循环。这些显示规则不要求先导入参数表。详见[自检与预处理](../docs/规格/上电自检与传感器预处理.md)。

RGB氛围灯由宿主绑定 `hmi_ops.set_ambient_rgb(red, green, blue, ctx)`。APL在 10ms 业务帧末尾提供已合并亮度的实际通道值，首个业务帧同步、之后仅在变化时通知，熄灭为(0,0,0)。使用 1ms 入口时首次回调发生于第 10 次调用。网页仿真使用同一回调输出；具体硬件接法与完整宿主约定见[宿主接入要求](宿主接入要求.md#4-rgb-氛围灯输出约定)。

## 6. 导入参数与错误处理

宿主先完整接收配置，检查存储有效性和传输完整性，再逐字段解码为 `struct apl_profile`，最后用 `apl_profile_validate` 校验或直接交给 `apl_init_profile`。创建配置副本时先调用 `apl_profile_defaults`，再覆盖产品需要的字段。

- 没有已导入的表：向初始化入口传 `NULL`，使用固件缺省表。
- 已有有效表：传表地址，成功后 APL 复制保存；调用方可复用接收缓冲区。
- 非空表版本、能力或值不合法：返回对应错误，原对象不变。宿主可记录错误，在冷启动时显式传 `NULL` 回退；不能忽略错误继续推进未初始化对象。

APL 不读写 Flash。`struct apl_profile` 含平台相关布局，不能直接当串口报文或 Flash 格式传输。Modbus 地址、串口帧、掉电安全保存和参数写入工具仍待接入。

初始化接口仅用于停止 tick 且物理负载已关闭的冷启动。收到新参数时，宿主先停机和关闭负载，完成保存，再按启动流程加载；不要对正在运行的对象直接重新初始化。

### 配置内部按键映射

宿主继续用原来的 `get_key_state` 填写固定输入槽位，不改变GPIO、驱动绑定或输入编号。先生成默认参数，再按产品配置覆盖内部动作，例如交换 Light 和 Power 的短按行为：

```c
apl_profile_defaults(&profile);
#if APL_COMPILE_HMI && APL_HMI_COMPILE_KEYMAP
profile.keymap.enabled = 1u;
profile.keymap.short_action[APL_HMI_KEY_LIGHT] = APL_KEY_ACTION_POWER;
profile.keymap.short_action[APL_HMI_KEY_POWER] = APL_KEY_ACTION_LIGHT_TOGGLE;
#endif
/* 物理负载关闭、尚未启动tick。检查初始化结果，成功后再绑定。 */
result = apl_init_profile(&device, &core_ops, NULL, &hmi_ops, NULL, &profile);
if (APL_PROFILE_OK == result) { apl_link_bind(&device); }
```

短按与长按分别配置，未配置或 `keymap.enabled=0` 保持标准行为。映射随产品参数加载，APL复制持有，不属于掉电运行记忆。`key_event` 继续报告原始输入编号，例如 Light 输入执行电源动作时仍记录 Light 短按；观察回调不要再发控制命令。默认 Timer+Speed、Power+Timer 组合仍按原始输入识别。动作、童锁、唤醒和定时连增规则见[内部按键映射](按键映射.md)。

`APL_HMI_COMPILE_KEYMAP=0` 保留固定标准映射并移除自定义映射存储与专用API；宿主访问参数字段时使用上面的相同守卫。单独使用HMI时，`apl_hmi_set_keymap`借用调用方的表，表必须在HMI使用期间持续有效且不可修改；组合对象使用实例内部持有的表，不依赖初始化输入缓冲区。

## 7. 掉电记忆

产品参数和运行记忆分别保存。`core_ops.memory_save` 交出的是 `struct apl_core_memory`，不包含产品参数；宿主负责持久化。启动时先加载产品参数，再通过 `apl_core_memory_restore` 恢复属于同一产品的运行记忆，最后开始 tick。

记忆保存用户档位等已有运行信息，不另存每档 rpm。恢复同一档位时，会使用本次加载参数里的目标转速。不要把其他产品的旧运行记忆直接交给当前产品。

## 8. 在 Studio 中试用

在 Web Studio 中新建产品、选择净化/加湿功能、修改参数并保存，然后启动仿真。新建产品的五档 rpm 使用本说明中的缺省值；仿真同时显示最终档位和目标转速，转速变化会进入事件记录。

APL 源码或参数定义更新后，重启 Studio，在产品“版本与来源”中确认绑定当前源码，保存并重新启动仿真。旧 v1/v2/v3 产品补齐缺失 rpm 时采用当前缺省值。**已经存在的 v4 转速，包括 0 和自定义值，会继续保留**，需要改变时请在产品配置里填写，不会因默认值更新而自动改写。

当前参数格式为 v6、定义修订7；v5增加Wi-Fi产品PID，v6增加内部按键映射。旧产品确认绑定当前源码后补齐新增默认值，已有PID、转速和其他产品参数继续保留，缺少映射时保持标准布局。Studio“按键映射”可分别选择短按、长按动作，再保存、仿真和导出。Excel增加同名工作表，当前尚不能直接串口烧入设备。

## 9. 维护与验证

本说明随 APL 接口、缺省行为和接入顺序更新。涉及参数变化时，同时维护 C 定义、`parameters/profile.schema.json`、三个产品示例、Excel 模板和相关 Studio 说明；修改默认值不能覆盖用户已经保存的配置。

在仓库根运行：

```powershell
python tools/check_parameters.py
python tests/run_platform_checks.py
```

在 `apl_studio` 目录运行 `npm run check`，验证类型、网页构建和 Studio 测试。主机测试验证 APL 目标输出与配置行为，实际电机调速和存储写入需在宿主设备上验证。
