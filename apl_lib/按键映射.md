# APL 内部按键映射

这项配置只改变标准联动面板的 **输入手势 → 业务动作** 映射。宿主采样方式、GPIO 和触摸绑定、`struct apl_hmi_key_state` 字段、`enum apl_hmi_key_id` 编号保持不变。

一般产品通过 `struct apl_profile.keymap` 配置，并使用 `apl_init_profile`、`apl_link_bind` 初始化。Studio 的对应操作见 [按键动作映射](../apl_studio/docs/按键映射.md)。

## 固定输入与配置结构

```c
#define APL_KEYMAP_COUNT 7u

struct apl_keymap {
    uint8_t enabled;
    uint8_t short_action[APL_KEYMAP_COUNT];
    uint8_t long_action[APL_KEYMAP_COUNT];
};
```

| 下标 | 输入枚举 | 宿主采样字段 |
|---|---|---|
| 0 | APL_HMI_KEY_PURIFY | purify |
| 1 | APL_HMI_KEY_HUMIDITY | humidity |
| 2 | APL_HMI_KEY_TIMER | timer |
| 3 | APL_HMI_KEY_LIGHT | light |
| 4 | APL_HMI_KEY_SPEED | speed |
| 5 | APL_HMI_KEY_POWER | power |
| 6 | APL_HMI_KEY_FILTER | filter |

`enabled=0` 保留原有标准策略；`enabled=1` 使用两组完整数组。`enabled` 必须是 0 或 1，每项动作必须是合法编号。数组使用 `uint8_t` 保存动作编号，不能改为依赖编译器宽度的枚举数组。

`apl_profile_defaults` 设置 `enabled=0`，并填入标准动作：

```text
short_action = {5, 10, 7, 9, 3, 1, 12}
long_action  = {6, 11, 8, 0, 4, 2, 13}
```

启用自定义映射后，`NONE` 明确表示无动作，不回退到原始键功能。手势仍由 APL 识别：松开触发短按；持续 3 秒触发一次长按，松开不再补短按。

## 动作编号

以下枚举在 `apl_type.h` 定义，编号固定。

| 编号 | APL_KEY_ACTION_ 后缀 | 含义 |
|---|---|---|
| 0 | NONE | 不执行业务动作，不唤醒显示 |
| 1 | POWER | 电源开关；保留标准产测退出 / 恢复行为 |
| 2 | DRY_STOP | 结束关机风干 |
| 3 | FAN_CYCLE | 按标准顺序切换风档 |
| 4 | TURBO_TOGGLE | 进入或退出极速 |
| 5 | PURIFY_TOGGLE | 标准净化复合开关，受 UV、负离子选配约束 |
| 6 | WIFI_PAIR | 清除网络并进入配网 |
| 7 | TIMER_EDIT | 按配置步进编辑定时；映射到短按时保留按住连增 |
| 8 | CHILD_LOCK_TOGGLE | 开启或解除童锁 |
| 9 | LIGHT_TOGGLE | 切换整块面板灯光 |
| 10 | HUMIDITY_CYCLE | 原湿度短按行为：一体机切换加湿，纯加湿机编辑目标湿度 |
| 11 | HUMIDITY_EDIT | 原湿度长按行为：一体机进入目标湿度编辑 |
| 12 | FILTER_QUERY | 纯净化机查询滤芯寿命 |
| 13 | FILTER_RESET_QUERY | 纯净化机复位并显示滤芯寿命 |
| 14 | SLEEP_TOGGLE | 进入或退出睡眠模式 |
| 15 | HUMIDIFY_TOGGLE | 直接切换加湿，不进入目标湿度编辑 |

动作的运行状态、传感器和功能前提仍按 APL 业务检查。映射到其他输入不绕过这些检查。对应功能未启用或被裁剪时不执行该动作，映射值仍可保留；例如关闭 Wi-Fi 后可以保留配网动作编号。

定时设置页内，短按映射为TIMER_EDIT的输入按住时执行连增，并消费该次手势；不会再补发其长按动作。设置页外仍按3秒判定长按。

童锁解锁按映射后的童锁动作判断，而不是硬编码为 `Timer` 输入。组合键仍按原始输入识别：标准 `Timer + Speed` 复位滤网，`Power + Timer` 进入产测，持续 3 秒；它们不随单键映射移动。

## 推荐初始化

先生成默认参数，再覆盖产品字段，校验并初始化。下面把 `Light` 和 `Power` 两个输入的短按功能交换，宿主采样代码无需修改。

```c
#include "apl.h"

static struct apl device;
static struct apl_profile product_profile;

enum apl_profile_result app_apl_init(
    const struct apl_core_ops *core_ops, void *core_ctx,
    const struct apl_hmi_ops *hmi_ops, void *hmi_ctx)
{
    enum apl_profile_result result;

    apl_profile_defaults(&product_profile);
#if APL_COMPILE_HMI && APL_HMI_COMPILE_KEYMAP
    product_profile.keymap.enabled = 1u;
    product_profile.keymap.short_action[APL_HMI_KEY_LIGHT] =
        APL_KEY_ACTION_POWER;
    product_profile.keymap.short_action[APL_HMI_KEY_POWER] =
        APL_KEY_ACTION_LIGHT_TOGGLE;
#endif
    result = apl_init_profile(&device, core_ops, core_ctx,
                              hmi_ops, hmi_ctx, &product_profile);
    if (APL_PROFILE_OK == result) {
        apl_link_bind(&device);
    }
    return result;
}
```

宿主每 1 ms 串行调用 `apl_tick_1ms(&device)`，由 APL 内部分频到原有业务节拍。不要与 `apl_tick` 或分模块 tick 混用。

`apl_init_profile` 将参数复制到主控持有的配置中，组合根自动把该配置内的映射表交给 HMI。传入配置只需在初始化调用期间有效。若宿主为了后续读写另行保留完整配置副本，其内存需要单独计入预算。

修改参数采用冷启动流程：停止 tick，确保物理负载关闭，重新准备并验证整表，调用 `apl_init_profile`，成功后再次 `apl_link_bind`。不支持并发修改映射表或在 tick / 回调中热切换。校验失败不替换现有对象；宿主负责决定如何处理失败。

## 单独配置 HMI

```c
#if APL_HMI_COMPILE_KEYMAP
void apl_hmi_set_keymap(struct apl_hmi *self,
                        const struct apl_keymap *keymap) APL_CALL;
#endif
```

此接口只借用 `const` 指针，不复制表。传入的表必须在 HMI 使用期间持续有效，不得指向已经退出作用域的局部变量，也不得被并发修改。仅在 HMI 初始化后、停止 tick 时配置；重新初始化 HMI 会清除旧绑定。传入 `NULL` 或 `enabled=0` 恢复标准策略。

映射只影响 `apl_hmi_link_bind` 后的标准联动面板。单独使用 HMI 自定义按键回调时，回调仍按原始输入槽位分发。使用组合根时优先通过 `apl_profile` 设置；`apl_link_bind` 会重新绑定主控所持有的映射。

`ops.key_event` 是观察通知，保留原始输入编号与短按 / 长按标记，不应在其中重复执行映射后的控制。业务动作、显示变化和宿主负载变化是不同层次的信息。

## 裁剪、版本和内存

映射由 `APL_HMI_COMPILE_KEYMAP` 控制，使用它还需要 `APL_COMPILE_HMI=1`。所有编译单元必须使用同一份配置宏。

- `APL_HMI_COMPILE_KEYMAP=0`：不提供 `apl_hmi_set_keymap`，主控参数不含 `keymap` 字段，HMI 不保存映射指针；标准按键策略保留。
- `APL_COMPILE_HMI=0`：整个 APL 按键和显示被裁掉，宿主自行处理交互，主控参数不保存映射表。
- 具体输入的 `APL_HMI_COMPILE_KEY_*` 关闭时，仍保留编号，但不识别该输入的手势。

当前参数格式为 **v6**。C 内存结构随功能裁剪、编译器对齐和指针模型变化，禁止直接将 `sizeof(struct apl_profile)` 个字节作为串口协议或 Flash 存储格式。宿主应按协议解码字段，填入先经 `apl_profile_defaults` 初始化的当前版本结构，再校验加载。

当前 Keil C51 LARGE 布局中，开启映射增加 15 B 主控配置与 3 B HMI 指针，共 **18 B 实例静态空间**。单独保留的参数副本每份也增加 15 B。关闭映射可裁掉相关字段与执行代码；具体 Flash 节省、最终 XDATA 和软件栈预算以完整宿主工程重新链接的结果为准。
