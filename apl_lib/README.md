# APL C业务库

编译裁剪已推广到净化/加湿、UV/负离子、传感器以及定时、滤网、产测、运行记忆、睡眠、风干和氛围灯。开关统一见`config/apl_build_config.h`；关闭后移除专属实现、参数/私有状态及专用API，通用协议与硬件回调槽位保留。[裁剪边界与验证](../docs/规范/APL模块解耦与裁剪.md)。

Wi-Fi已支持[模块解耦与彻底裁剪](../docs/规范/APL模块解耦与裁剪.md)：`APL_COMPILE_WIFI=0`移除状态机、专用API及PID/配网参数存储；全功能工程新增编译`src/apl_wifi.c`，关闭时可不加入该文件。

编译裁剪：[开关、资源测量与移植示例](../docs/规范/APL编译裁剪.md)。默认全功能；C51可选择保留标准面板的407字节实例或宿主自带交互的176字节纯主控实例。

C51 内存与性能：[优化记录及复测方法](../docs/规范/APL内存与性能优化.md)。当前 Keil LARGE 下每个组合实例默认预留516字节，裁掉内部按键映射后为498字节；宿主与库需配套重新编译。

移植入口：[使用说明](使用说明.md) · [宿主接入要求](宿主接入要求.md)。推荐每 `APL_TICK_MS`（1ms）调用 `apl_tick_1ms`，各实例独立累计 10 次后推进一个 10ms 业务帧。原 `apl_tick`、`apl_core_tick`、`apl_hmi_tick` 保留 10ms 语义，不得在同一实例上混用新旧推进方式。

宿主通过 `hmi_ops.set_ambient_rgb` 提供RGB驱动，APL在业务帧末尾按最终显示状态、合并亮度后通知输出变化；首次同步发生于第一个 10ms 业务帧，Web仿真使用相同RGB值。

新增产品规则：上电全灯自检2秒后恢复显示，开机后PM2.5/湿度预处理5秒，三位横段同步向下流水；接口及验证见[上电自检与传感器预处理](../docs/规格/上电自检与传感器预处理.md)。

当前开发版 0.3.0 新增运行时产品方案：同一全功能固件在冷初始化时加载不同参数，决定净化/加湿能力、模块与传感器选配及运行参数。接口与范围见 [运行时参数配置](../docs/规格/APL运行时参数配置.md)。传输协议、配置持久化及 Studio 参数交付尚未接入；冻结模板不自动更新。

产品参数定义、Excel 默认模板及三机型示例统一在 [parameters](parameters/README.md) 管理，随 APL 源码版本一起提交；`python tools/check_parameters.py` 可从工程根核对表格和实际 C 定义。

当前参数格式v6、定义修订7支持[内部按键映射](按键映射.md)：分别配置七个固定输入的短按、长按动作，宿主GPIO和输入编号保持原样。缺少映射或关闭自定义时沿用标准面板行为，事件仍显示原始输入；组合键继续使用原始输入组合。Studio和Excel提供相应配置，`APL_HMI_COMPILE_KEYMAP=0`可移除自定义映射。

未导入参数表也可启动：`apl_init_profile(..., NULL)`使用固件内置缺省表并返回`APL_PROFILE_OK`，随后调用`apl_link_bind`并按拍推进；与原`apl_init`的缺省配置一致。已导入的非空表仍须通过完整校验，错误不会被静默覆盖；宿主负责存储判定和持久化。各档目标转速缺省为400/600/900/1200/1500 rpm，可按产品覆盖。宿主完整接入与维护入口见[APL使用说明](使用说明.md)。完整接入示例见[运行时参数配置](../docs/规格/APL运行时参数配置.md#尚未导入参数表)。

本目录是唯一的APL业务开发源，由原工程根的三个目录整体移动而来：

```text
apl_lib/
├── src/      C业务实现
├── include/  公开头与对象接口
└── config/   能力编译开关、默认值与参数
```

内部头文件名、C接口、对象占位、版本和文件内容保持不变。宿主持有`struct apl`，通过ops注入硬件；能力对象组合方向见[重构说明](../docs/规范/APL能力组合重构.md)。

从仓库根编译：源码列为`apl_lib/src/apl.c`、`apl_lib/src/apl_core.c`、`apl_lib/src/apl_hmi.c`、`apl_lib/src/apl_wifi.c`，头文件搜索目录为`apl_lib/include`、`apl_lib/config`。库内注释中的`src/include/config`路径相对于本目录。

测试仍放在仓库根`tests/`，各测试文件头给出编译方式。行为trace和资源对比：

```powershell
& ./tests/compare_output_trace.ps1
```

脚本支持迁移前、后的Git基线路径；默认保留固定业务基线749c6fc。仅验证此次目录整理可传入`-BaselineRef fbd0308`。

`apl_sdk_template/air-care/<版本>`是不可变的本地Web/SDK快照，内部仍使用`src/include/config`；目录移动不改变快照内容、版本、来源哈希或产品绑定，也不会将根库修改自动同步到Web。冻结步骤见[源码与版本快照](../apl_studio/docs/APL源码与版本快照.md)。

本次不执行Qt、设备或真实数据库，不修改业务策略；工作簿中的三项湿度规则仍待确认。

## 目录迁移检查点

- 9个库文件移动前后原始SHA256完全一致，Git识别为100%重命名；根目录不保留第二份源码或兼容副本。
- 对迁移前提交`fbd0308`执行trace比较，三配置共35878条记录完全相同；公开符号、对象尺寸、代码段、静态RAM与tick静态栈测量均无变化。
- 新路径编译的原有根C回归共12组通过；Studio完整类型检查、Web构建和34项测试通过，失败/跳过0。包含新旧版本真实C运行、SDK生成/编译/消费、来源与归档哈希及下载；其中4项暂停组合键测试不纳入此提交或新规格验收。
- 审查24处库文档链接均可解析，旧CMake库路径均指向存在的新目录。旧Qt仅同步必要路径和源码发现入口，未编译或运行Qt，因此不宣称Qt运行验收。
- 已冻结版本未修改。保留的`src/include/config`引用分别属于库内或SDK相对目录、历史Git基线及Changelog历史条目；Web生成器不读取开发库，不能将目录整理视为新模板发布。
- 7个组合键文件、`.vscode/`和用户工作簿保留且不混入迁移提交。
