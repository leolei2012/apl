# APL C业务库

本目录是唯一的APL业务开发源，由原工程根的三个目录整体移动而来：

```text
apl_lib/
├── src/      C业务实现
├── include/  公开头与对象接口
└── config/   能力编译开关、默认值与参数
```

内部头文件名、C接口、对象占位、版本和文件内容保持不变。宿主持有`struct apl`，通过ops注入硬件；能力对象组合方向见[重构说明](../docs/规范/APL能力组合重构.md)。

从仓库根编译：源码列为`apl_lib/src/apl.c`、`apl_lib/src/apl_core.c`、`apl_lib/src/apl_hmi.c`，头文件搜索目录为`apl_lib/include`、`apl_lib/config`。库内注释中的`src/include/config`路径相对于本目录。

测试仍放在仓库根`tests/`，各测试文件头给出编译方式。行为trace和资源对比：

```powershell
& ./tests/compare_output_trace.ps1
```

脚本支持迁移前、后的Git基线路径；默认保留固定业务基线749c6fc。仅验证此次目录整理可传入`-BaselineRef fbd0308`。

`apl_sdk_template/air-care/<版本>`是不可变的本地Web/SDK快照，内部仍使用`src/include/config`；目录移动不改变快照内容、版本、来源哈希或产品绑定，也不会将根库修改自动同步到Web。冻结步骤见[源码与版本快照](../apl_studio/docs/APL源码与版本快照.md)。

本次不执行Qt、设备或真实数据库，不修改业务策略；工作簿中的三项湿度规则仍待确认。

## 目录迁移检查点

- 9个库文件移动前后原始SHA256完全一致，Git识别为100%重命名；根目录不保留第二份源码或兼容副本。
- 对迁移前提交`fbd0308`执行trace比较，三配置共35878条记录完全相同；公开符号、对象尺寸、代码段、静态RAM与tick静态栈测量均无变化。
- 新路径编译的原有根C回归共12组通过；Studio完整类型检查、Web构建和34项测试通过，失败/跳过0。包含新旧版本真实C运行、SDK生成/编译/消费、来源与归档哈希及下载；其中4项暂停组合键测试不纳入此提交或新规格验收。
- 审查24处库文档链接均可解析，旧CMake库路径均指向存在的新目录。旧Qt仅同步必要路径和源码发现入口，未编译或运行Qt，因此不宣称Qt运行验收。
- 已冻结版本未修改。保留的`src/include/config`引用分别属于库内或SDK相对目录、历史Git基线及Changelog历史条目；Web生成器不读取开发库，不能将目录整理视为新模板发布。
- 7个组合键文件、`.vscode/`和用户工作簿保留且不混入迁移提交。
