# 上电自检与传感器预处理

适用当前 APL 0.3.0 开发源及 Studio 本地运行时参数仿真；既有冻结模板保持各自行为。

## 已确认的产品逻辑

1. 接通电源后，面板全灯自检持续2秒，数码管显示888。未编译的按键/面板灯位不作虚构输出；功能未配置的灯位仍遵守现有屏蔽规则。
2. 自检结束的同一拍按上电恢复状态显示：待机熄灭数显并保留电源键灯；恢复运行显示记忆的运行状态和对应档位指示。沿用待机电源灯128亮度，没有把“亮”擅自改成新的亮度要求。
3. 每次进入开机运行，PM2.5及湿度传感器至少预处理5秒，运行档位指示灯照常显示。掉电后恢复运行、风干中重新开机同样重新计时。长时间待机不能抵扣这5秒。
4. 预处理显示为三位数码管的横段**同时**按上段→中段→下段循环。当前采用每段300ms，一圈900ms；三位同步，单位灯关闭。
5. 5秒到时仍需驱动报告有效状态才读取正常数值；驱动仍在预处理则继续显示横段，驱动明确故障不因超时变为有效。已有故障、设置预览、睡眠熄屏及灯光优先级保留。

2秒自检从接电开始，5秒预处理从进入运行开始，两者是独立时钟。若上电即恢复运行，它们会重叠；不是一律等待7秒。普通待机后按电源开机，则从此次开机重新计满5秒。

运行中手动关灯遵循用户2026-11-03确认的“全灭”规则：按键背光、数显/单位、状态图标（包括Sleep）、水位灯和氛围灯均熄灭，预处理照常计时。首次有效按键只临时唤醒，3秒无操作后再次全灭。自动睡眠、自检、待机和风干仍按各自状态规则显示。

## 实现及接口

- 宿主推荐每1ms调用 `apl_tick_1ms`，内部每10次调用推进一个10ms业务帧；主控按业务帧递减运行预处理计时，在第500个业务帧重新检查输入，并在该帧采样，避免被全局每秒采样相位额外推迟。上电自检仍为200个业务帧（2秒），预处理仍为500个业务帧（5秒）。旧 `apl_tick` 仍每10ms调用，禁止与新入口混用。
- 预处理期间已选配的PM2.5/湿度输入不会进入 `sensors_ready`，也不调用其正常数值回调；自动/恒湿不拿默认零值当真实输入。PM10、甲醛、TVOC维持各自的驱动状态规则，本条没有新增它们的固定延时。
- 开机时不等待传感器才启动手动风机；自动预处理阶段沿用开机物理档。连续加湿、有效水位、安全联锁等既有规则保留。
- HMI从主控 `sensors_warming` 驱动横段动画；网页仅映射实际C字符，不另设前端动画时钟。`get_digits_content`的`^^^`、`---`、`___`分别是上、中、下横段的诊断编码，显示端不能将`^`画成箭头。
- Studio参数工作台每100ms读取一次实际C快照，与后端自动推进节奏一致；不能使用500ms刷新去观察300ms的横段帧，否则会跳过动画阶段。浏览器后台限速或请求延迟仍可能导致丢帧，重新可见时显示最新实际状态。
- 新增 `apl_hmi_get_digit_segments(self, index)`，index为0～2。标准逻辑位为A上段bit0、B右上bit1、C右下bit2、D下段bit3、E左下bit4、F左上bit5、G中段bit6。三个横段掩码分别为0x01、0x40、0x08；亮度另取getter。实际驱动按硬件接线映射段位，不依赖C内存布局。

## 验证

`tests/test_startup_preprocess.c`覆盖199/200拍自检边界、499/500拍预处理边界、非整秒时刻开机、三位段掩码、掉电恢复档位、延迟有效和故障；在纯净化、纯加湿及一体机编译配置中执行。Studio运行时参数闭环也检查三位横段帧以及5秒前后实际C数显。

本轮根库70项本机C回归通过，参数表与实际C定义一致性检查通过。目标MCU的物理段线和传感器驱动仍需硬件验收。
