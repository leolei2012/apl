## 1. 目的与范围

本文定义库对象 `struct apl_hmi` 的职责，以及它与 `struct apl_core` 之间的数据边界。

本仓库是库，库内不创建实例。使用方持有 `struct apl`，人机是其中的 `struct apl_hmi`。人机对象不包含 `apl_core`，也不读取主控的 [`config/apl_core_config.h`](../../config/apl_core_config.h)。人机自己的编译控制和默认值在 [`config/apl_hmi_config.h`](../../config/apl_hmi_config.h)。`apl_init` 与 `apl_tick` 在 `src/apl.c`。

空气净化与加湿是否启用由主控的动态配置决定。人机按快照绘制：动态配置未启用或未编译的功能不画。

人机负责：

- 采集按键、触摸等用户操作
- 把会改变机器行为的操作交给主控
- 按主控快照绘制屏、指示灯

人机不负责：模式判断、档位计算、恒湿、滤网寿命、缺水判断、故障判定、风机与雾化输出。这些属于 [apl后端规格书](./apl后端规格书.md)。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 人机 / `apl_hmi` | 库对象 `struct apl_hmi`。本文描述这个对象 |
| 主控 / `apl_core` | 库对象 `struct apl_core`，见后端规格书 |
| `link_command` | 人机发给主控的操作 |
| `link_snapshot` | 主控发给人机的状态快照 |
| 动态配置 | 主控运行中可修改的配置。快照给出当前启用了净化、加湿中的哪几项 |

对象方法以 `apl_hmi_` 为前缀，`self` 为第一个参数。库内不放 `static struct apl_hmi`。协议结构以数据命名（`link_command`、`link_snapshot`），不把传输方向写进类型名。

## 3. 与主控的边界

判断和执行在主控。人机是操作的入口和状态的出口。

```text
用户操作 → hmi → link_command → core
core → link_snapshot → hmi → 屏 / 灯
```

规则：

1. 会改变运行行为的按键，在认出短按或长按后调用该键的回调。使用方在回调里形成 `link_command`。人机不在回调里改模式、档位、目标湿度或执行器。
2. 屏和灯只反映最新一份 `link_snapshot`。人机不用本地猜测补全主控还没确认的状态。
3. 快照标明某项功能未启用时，人机不绘制该项的图标、数值和操作入口。
4. 同一套界面逻辑覆盖全部动态配置。画不画净化、加湿，只看快照。

按键电平由宿主在 `apl_hmi_init` 注入的 `key_state_get` 一次给出六颗键。`apl_hmi_init` 让已编入的灯和三位数字管全亮，数字为 888；200 拍后熄灭，电源键半亮。使用方每 10 ms 调用 `apl_tick`，其中再调用 `apl_hmi_tick`。全亮阶段 `apl_hmi_powerup_lamp_get` 返回 1，使用方不要覆盖这些灯。短按在松开时发出，按下满 3 秒发出长按，同一次按下不重复。宿主和人机交换显示、童锁、启用标志和键回调时走 getter 和 setter。童锁、组合键和对象属性见 [HMI Datasheet](./datasheet.md)。

命令的具体种类、快照字段、字节协议和断连表现待定。确定后记入本文第 5、6 节，并与后端规格书保持同一份定义。

## 4. 配置

[`config/apl_hmi_config.h`](../../config/apl_hmi_config.h) 只做人机的编译控制和默认值。主控的 `apl_core_config.h` 不包含面板。

### 4.1 编译控制

`APL_HMI_PANEL` 选定一块按键/显示面板。对外仍是一个 `struct apl_hmi`，构建只编进该面板的实现。换面板改这个宏并换上对应实现，使用方的实例和调用不变。

| 宏 | 含义 | 未设置时 |
|---|---|---|
| `APL_HMI_PANEL` | 已登记的面板标识 | `APL_HMI_PANEL_UNSPECIFIED`（0，尚未指定） |
| `APL_HMI_COMPILE_KEY_PURIFY` | 是否编入净化键 | 1 |
| `APL_HMI_COMPILE_KEY_HUMIDITY` | 是否编入加湿键 | 1 |
| `APL_HMI_COMPILE_KEY_TIMER` | 是否编入定时键 | 1 |
| `APL_HMI_COMPILE_KEY_LIGHT` | 是否编入灯光键 | 1 |
| `APL_HMI_COMPILE_KEY_SPEED` | 是否编入风速键 | 1 |
| `APL_HMI_COMPILE_KEY_POWER` | 是否编入电源键 | 1 |

取值必须是头文件里登记过的标识，否则编译报错。具体面板待硬件确定后登记。六颗键各自选配，只能是 0 或 1，可用 `-D` 覆盖。未编入的键不认短按、长按和组合，键灯读写视为非法。键编号保持不变，采样结构仍给出六颗键的电平，库丢掉未编入的那一颗。可以六颗都不编入。这与净化、加湿的运行时启用无关。功能启用不在本文件：画不画净化、加湿，只看主控快照。

### 4.2 默认值

人机本地行为的默认值放在这个头文件。目标湿度、档位等业务默认值放在主控的 `apl_core_config.h`。当前尚无已确认的人机默认值。

## 6. 显示（link_snapshot）

当前这块面板的六个按键、键下灯、氛围灯和数码管对象见 [HMI Datasheet](./datasheet.md)。快照里每个字段如何写到这些对象上，待定。

已确认的显示规则：

- 绘制内容来自快照。
- 动态配置未启用的功能不出现在界面上。
- 故障码、模式、档位的含义以主控定义为准，人机只做呈现。

页面结构、刷新率和亮灭策略待定。
