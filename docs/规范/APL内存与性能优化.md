# APL 内存与性能优化

适用于 `apl_lib` 当前 0.3.0 开发源码。优先目标为 Keil C51 / 8051；宿主、库和头文件必须配套重新编译。冻结 SDK 不随本次修改改变。

后续已增加可选[编译裁剪](APL编译裁剪.md)：下文481字节及390/356/159字节是新增PID前的历史测量。参数格式v5保存PID后各实例增加17 B，v5默认498 B、裁剪407/373/176 B；v6加入内部按键映射后，默认516 B、裁剪425/391/176 B（KEYMAP=1，纯主控不计映射）；对应接口限制以裁剪文档为准。

## 已完成的优化

使用本机 Keil C51 9.60.7.0、LARGE、`OPTIMIZE(8,SIZE)` 编译包含实际库源码的隔离探针，直接读取编译器生成的 `sizeof` 常量。三种净化/加湿编译组合结果相同：

| 对象 | 原预留字节 | 当前预留字节 | 当前实际状态字节 |
|---|---:|---:|---:|
| 主控 `struct apl_core` | 320 | 160 | 149 |
| 人机 `struct apl_hmi` | 1024 | 320 | 296 |
| 组合 `struct apl`，含 1ms 调度余数 | 1345 | 481 | — |

每个 C51 实例节省 864 字节，约 64.2%。主控保留 11 字节余量，人机保留 24 字节余量；其中主控实际状态从第一轮的147字节增加为149字节，新增两个百分比缓存字节，实例预留不变。原有内部状态大小和对齐静态断言保留；后续字段增长超出容量会编译失败，不会悄悄越界。宿主若将实例放在 XDATA，就相应减少该实例的 XDATA 预留。

缩减由 `__C51__` 平台分支决定；原生 GCC 的占位对象布局保持原样。当前 Windows x64 GCC 的组合对象为 1352 字节，主控状态224字节（增加缓存前为216字节，差别包含对齐）、人机状态592字节，不能拿它们代替C51的布局数据。其他编译器应以自己的编译结果和静态断言为准。

滤网剩余百分比仍是 `ceil((life-used)*99/life)`。实现改用 99 的七位二进制逐位运算，将每次调用的 99 轮累加改为 7 轮；余数始终小于寿命总秒数，不依赖 64 位整数，也不溢出最大 1000000 小时的配置。边界、随机值和取整由现有独立 `uint64_t` 主机 oracle 校验。

这是计算量与代码空间的取舍：相同 Keil 设置下，一体机隔离探针的 CODE 从 33936 增至 34084 字节，增加 148 字节。这些数字包含整个探针中的库函数，不是最终固件链接后的 Flash 占用。减少循环次数不等于已测得 MCU 加速倍数，真实耗时还需目标测量。

## 第二轮：快照直写与滤网缓存

组合tick在主控推进后，将完整快照直接写入当前HMI实例自己的快照缓冲区，再提交首帧标志和启用状态，最后执行HMI。去掉51字节的局部快照及一次结构体复制，保留主控→快照→HMI顺序和首次快照不补播历史提示音的语义。内部缓冲入口仅声明在 `apl_internal.h`，宿主不得取得或保留其指针；没有新增全局共享缓存。独立宿主的 `apl_hmi_set_snapshot` 仍复制传入的数据。

Keil单独编译 `apl.c` 的汇编显示，`apl_tick` 入口固定XBP预留从54字节（3字节self参数＋51字节局部快照）降为3字节。函数调用过程中仍有参数临时压栈、被调函数和宿主回调开销，所以此数不代表整个调用链最坏栈；不能据此直接将目标软件栈预算减少51字节。

主控保存净化/加湿两个剩余百分比，`apl_core_get_snapshot` 只读取它们，不再执行百分比计算，也不修改对象。运行期间随每秒计数更新缓存；初始化、记忆恢复、独立复位接口、复位命令、产测注入及产测退出恢复也同步更新，并在通知宿主前完成。纯读取快照或停机不重复计算，变化后读取无须等待下一拍。

相对于第一轮，三种组合的实例预留均保持481字节。一体机探针CODE从34084增到34336字节（+252）；纯净化33633→33870，纯加湿31796→32033。这里用少量代码换取更小的临时栈和更低的计算频率；未声称实机加速比例。

## 复现与维护

在工程根目录运行：

```powershell
python tools/check_memory.py --c51 C:/Keil_v5/C51/BIN/C51.exe --report apl_studio/output/memory/sizes.json
python tests/run_platform_checks.py --report apl_studio/output/memory/platform-report.json
```

不传 `--c51` 时只测量本机 GCC，不会伪装成 C51 结果。工具不下载编译器、不连接硬件；临时探针在临时目录中编译，JSON 是测量收据。C51结果另有 `tick_entry_frame_bytes`，仅解析单独编译组合根后的入口固定XBP预留，不含调用链和临时spill。修改内部字段、编译能力或调用约定后应重新测量；当前工具的C51实例超过516字节预算会报错。

Studio 的生成与真实 C 运行回归可以额外启用目标编译器：

```powershell
cd apl_studio
$env:CC = 'C:/Qt/Tools/mingw1310_64/bin/gcc.exe'
$env:PATH = 'C:/Qt/Tools/mingw1310_64/bin;' + $env:PATH
$env:APL_STUDIO_C51 = 'C:/Keil_v5/C51/BIN/C51.exe'
npx --no-install tsx --test tests/portable-c51.test.ts tests/runtime-profile.test.ts
```

参数结构的版本和内容没有改变；实例占位对象不属于 Flash/串口数据格式。不要把 `sizeof(struct apl)` 或它的原始字节写入掉电记忆；仍按[宿主接入要求](../../apl_lib/宿主接入要求.md)逐字段编码。

第二轮验证：79项主机平台/行为检查通过（第一轮为76项）；上述Studio生成、参数仿真及可选Keil编译回归5项通过；三种产品组合的Keil尺寸探针及独立组合根编译均为0警告、0错误。新增回归覆盖每秒到期、回调读取、独立/命令复位、产测注入及退出、产测中断记忆恢复、寿命参数更换、只读getter不修改对象，以及2000帧直写/复制路径的状态和显示等价。未烧录芯片，也未测量实际目标的最坏栈或时间。

## 后续可优化点

这些是后续方向，本次未实施：

1. **按产品裁剪 HMI 存储。** 当前无论纯净化、纯加湿还是一体机，状态布局相同。可按编译能力减少不使用的按键回调和组合槽位，但运行时产品仍必须保留当前固件承诺的完整能力。
2. **宿主只读表与回调开销。** 检查 ops 表、固定映射和提示文案的 CODE 放置；回调返回缓存的传感器数据，避免在 APL 调用链内等待外设。
3. **目标工程的栈与时序测量。** 测量带真实传感器、触摸、通信中断和宿主回调时的最坏软件栈和 tick 耗时。本文的对象尺寸、探针 CODE 和主机回归均不能替代实际固件链接、栈水位或实机时间。
