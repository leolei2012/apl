# APL模块解耦与编译裁剪

产品参数控制已经编入的能力是否启用；编译开关决定对应实现是否存在。裁剪按功能统一管理，不局限于Wi-Fi。关闭功能时，移除所属实现、私有状态、专用接口及无用参数存储；共用协议和宿主硬件接口保持明确边界。

## 实现边界

Wi-Fi有独立的`src/apl_wifi.c`和私有头`include/apl_wifi_internal.h`，可只链接该文件运行状态机测试。其他功能目前以`apl_core.c`、`apl_hmi.c`中的条件编译函数组实现，并非每项功能都拆成一个`.c`文件。主控负责跨功能策略和输出仲裁，面板只发送通用命令、读取快照，硬件访问通过宿主回调注入。

统一能力开关位于`config/apl_build_config.h`，默认保留现有功能。主要裁剪范围如下：

| 功能 | 编译开关 | 关闭后的边界 |
|---|---|---|
| 净化、加湿 | `APL_COMPILE_PURIFY`、`APL_COMPILE_HUMIDIFY` | 移除对应业务分支、私有运行状态及专用滤网/能力接口；加湿关闭后不采样水位、不调用泵回调 |
| UV、负离子 | `APL_COMPILE_UV`、`APL_COMPILE_ANION` | 移除对应输出、请求/故障状态、故障输入读取和命令处理 |
| Wi-Fi | `APL_COMPILE_WIFI` | 不提供连接/PID接口，不分配配网状态、计时、PID及配网超时参数；Studio不交付`apl_wifi.c` |
| 传感器 | `APL_COMPILE_SENSOR_PM25/PM10/HCHO/TVOC/HUMIDITY` | 不读取已裁掉的输入；对应采样/分级/显示分支及不再共用的缓存移除；全部传感器关闭时不保留共用预处理状态 |
| 极速 | `APL_CORE_HAS_TURBO` | 移除极速切换、恢复档、目标rpm及选配参数 |
| 定时 | `APL_COMPILE_TIMER` | 移除定时回调/计数、设置预览和连增；不提供`apl_core_set_timer/get_timer` |
| 滤网维护 | `APL_COMPILE_FILTER` | 移除寿命计数、百分比、复位/查询/闪烁及专用API；参数结构不再持有寿命和共用复位设置 |
| 产测 | `APL_COMPILE_FACTORY` | 移除入口、窗口计时、注入/恢复逻辑及CL显示；移除仅产测使用的滤网副本 |
| 运行记忆 | `APL_COMPILE_MEMORY` | 不提供记忆读取/恢复接口，不构造和通知记忆数据；只节省实现代码，首次开机语义共用的`used`状态仍保留 |
| 睡眠 | `APL_COMPILE_SLEEP` | 移除睡眠切换、恢复档、rpm和显示策略；配置/命令拒绝睡眠档，恢复旧记忆时忽略该档，循环与自动模式不输出睡眠档 |
| 风干 | `APL_COMPILE_DRY` | 移除风干入口、计时、运行历史及参数；正常关机仍关闭负载；仅在已编入加湿时生效 |
| RGB氛围灯 | `APL_HMI_COMPILE_AMBIENT` | 移除颜色/亮度缓存、输出及绘制，不提供四个ambient getter/setter |
| 蜂鸣器 | `APL_HMI_COMPILE_BUZZER` | 移除播放实现和状态，不提供播放/忙状态API；全部提示音与报警音均不发声 |
| 每键回调、组合键 | `APL_HMI_COMPILE_KEY_CALLBACKS`、`APL_HMI_COMBO_MAX` | 回调关闭或组合槽为0时，相关专用API不声明也不定义，不保留空实现 |

`APL_COMPILE_HMI=0`会移除整个HMI实例和实现，宿主负责按键、显示、童锁及交互策略。单个逻辑键也可通过`APL_HMI_COMPILE_KEY_*`关闭识别和灯位；通用键/图标/水位灯数组仍保留稳定编号，不能据此假定按键数量与RAM按比例缩减。

## 共用契约与依赖

通用命令ID、枚举及快照/运行记忆DTO保持稳定。已裁掉能力的快照字段为0，命令由通用拒绝分支处理。这些中性协议字段不表示对应业务实现仍存在。

宿主ops表的槽位及通用面板属性接口保持稳定；这些表由宿主持有，不能将其占用算成APL实例的自动节省。宿主应移除无用驱动文件、回调填充和调用引用；APL不会自动裁剪宿主工程的外设驱动。

净化和加湿至少编入一项。空气传感器依赖净化，湿度输入依赖加湿；风干只有与加湿同时编入才生效。UV联锁和缺水停泵随对应负载保留，不提供“保留负载、关闭保护”的开关。

定时功能与Timer物理键不是一对一关系：`TIMER=0`后，Timer长按童锁及使用该键的滤网/产测组合仍可存在。若还要移除这颗键，应单独裁掉逻辑键，并检查组合键入口是否仍适用。

## 宿主与参数接入

全功能工程编译`src/*.c`，头文件路径为`include`和`config`。Wi-Fi关闭时可以不加入`apl_wifi.c`；统一编译全部文件时，该翻译单元也不会产生模块实现。其他功能的裁剪由源码内条件编译完成。

专用API和字段必须使用同一开关保护，例如：

```c
#if APL_COMPILE_WIFI
char pid[APL_PRODUCT_PID_MAX + 1u];
apl_core_get_pid(&device.core, pid);
apl_core_set_wifi_connected(&device.core, network_connected);
#endif
#if APL_COMPILE_MEMORY
apl_core_get_memory(&device.core, &host_memory);
#endif
```

Studio生成的产品默认参数和仿真桥接会保护已裁掉的字段/接口。宿主手写代码未保护时，应编译失败，不能把缺失能力隐藏为空操作。所有库源文件和宿主须使用相同宏与配套头文件，并完整重新编译。

参数格式v6新增[内部按键映射](../../apl_lib/按键映射.md)，动作解析位于HMI，宿主采样输入不变。Studio及Excel/JSON可保留暂时未编入功能的参数，供以后重新启用；生成代码不会将这些值复制到不存在的C字段。物理结构布局随编译条件变化，禁止按裸`sizeof(struct apl_profile)`作为串口或Flash格式。

## 资源与验证

当前Keil C51 LARGE的测量如下。每格为“APL实例预留 / 隔离探针CODE”，不包含宿主、共享静态表和栈；探针CODE不能代替目标整机链接大小。

| 构建 | 纯净化 | 纯加湿 | 一体机 |
|---|---:|---:|---:|
| 各产品能力的缺省构建（v5历史测量） | 443 / 28836 B | 475 / 29923 B | 498 / 34605 B |
| 裁剪参考 | 208 / 11833 B | 241 / 15287 B | 242 / 15565 B |
| 裁剪参考再关闭HMI | 48 / 4314 B | 69 / 5933 B | 70 / 6211 B |

“裁剪参考”关闭新7项功能、蜂鸣器、每键回调、组合键、Wi-Fi、UV、负离子、极速及全部传感器；它是测量组合，不是Studio的“最小面板”预设。各产品缺省构建的净化相关模块/传感器随净化能力取默认值，例如纯加湿不默认编入UV和负离子。完整开关和收据见`apl_studio/output/memory/features-default.json`、`features-minimum.json`、`features-core-minimum.json`。

资源效果取决于同时保留的功能：共用状态只有在所有使用者都移除后才消失，MEMORY关闭主要节省代码。以内存估算、目标编译器`sizeof`及最终链接报告为依据，不为每个开关承诺固定节省量。

Studio共66项测试已通过并启用Keil C51检查；新增19种裁剪组合覆盖GCC宿主行为、消费端编译、专用公开/私有符号消失及Keil各源文件编译。另有22组新sizeof结果与内存公式一致。完整原生回归按其独立收据记录，Wi-Fi另有只链接独立模块的状态机测试。所有主机/隔离编译检查均不等于目标整机容量或硬件验收。

最终原生平台/行为回归137项通过，当前源码和头文件哈希与收据一致（`apl_studio/output/memory/feature-native-child.json`）；这些是库行为与编译证据，不是目标整机链接或硬件验收。

内部映射可由`APL_HMI_COMPILE_KEYMAP=0`独立裁剪。默认编入时，C51含HMI的实例在上述v5历史值上增加18 B，纯主控不变；CODE应重新编译测量，不能沿用历史值作为当前结果。
