# APL Studio

新增[内存估算](docs/内存估算.md)：根据裁剪计算APL分项，填写实例数量、其他数据、栈和安全余量，显示完整/未知/超限状态，并导出与产品修订关联的预算记录。

新增[固件裁剪与芯片预算](docs/固件裁剪与芯片预算.md)：配置产品时选择编译能力，仿真使用相同开关，并导出配套C源码包。资源预算不替代目标工程链接报告。

默认首页已改为参数工作台预览版：**新建产品 → 配置 → 仿真 → 导出 Excel**。当前接入本地 APL 0.3.0 运行时参数，说明见[参数工作台预览版](docs/参数工作台预览版.md)。旧 SDK 工程流程保留在 `/engineering`；下面有关模板和 SDK 的说明适用于该旧入口。历史 Git 版本选择、Modbus 串口写入仍待实现。

新建和配置产品时，独立勾选净化、加湿功能，不必单独选择一体机。圆形面贴按功能组合自动切换按键、单位和状态区域；至少启用一项。

“按键映射”支持分别选择固定输入的短按、长按动作，保持宿主输入绑定不变；保存后使用同一配置进行真实C仿真和导出。参数格式v6、定义修订7，旧产品确认更新版本绑定后缺省沿用标准映射。Excel导出新增“按键映射”页，源码参数包包含相同映射。说明见[按键映射](docs/按键映射.md)；编译关闭自定义映射时仍使用标准行为。

配置页按键以KEY1～KEY7展示，直接配置短按、长按动作并查看文字说明。选择运行参数后显示当前值的解释，保留恒湿回差、风干、目标转速、显示轮换和定时等参数示意。参数示意点击播放后只演示一次，可暂停、继续或重播；跟随系统“减少动态效果”偏好提供静态步骤。示意不发送设备仿真请求，实际业务仍在“仿真体验”中验证；无效数值不播放。

产品经理纯净化试点已提供中文方案、长按交互规则、真实C场景验收和工程师交付包。先看[一页手测与隔离启动说明](docs/产品经理纯净化闭环.md)；标准方案入口不要求填写代码标识、宏或C类型。历史工程配置与模板继续保留。

嵌入式产品标准化配置与 SDK 交付平台。平台统一产品模型、表单、校验、修订和交付；各品类模板提供业务源码、配置映射、硬件移植接口与验证程序。

AP 空气治理是第一个模板，另有独立 C11 灯控示例验证多品类流程。现有目录名、`product.apl.json`、`apl-sdk/` 和包格式标识沿用历史命名，不限制产品必须使用 APL 库。

## 启动

需要 Node.js ≥22.19.0、npm 和能够生成本机可执行程序的 GCC 兼容 C11 编译器。

```powershell
cd apl_studio
npm start
```

从APL仓库根目录先进入 `apl_studio`，再执行 `npm start`；与ProbeStation一样，先构建网页再启动服务。当前本机依赖已齐全，不需要重新安装；缺依赖时start.cmd只提示并退出，不自动安装。

访问 http://127.0.0.1:9190；Windows 也可双击 [start.cmd](start.cmd)。服务缺省监听本机9190，可通过`APL_STUDIO_HOST`、`APL_STUDIO_PORT`配置监听；端口占用时不自动换端口。启动前先检查端口，占用时显示中文提示并退出，数据库尚未打开；不停止其他进程。预检后若发生端口抢占，实际监听失败也会清理资源退出。

产品和修订持续保存在 `apl_studio/.data/studio.db`，SDK/验收资料在同一`.data`下；重启复用原数据，不每次生成空目录，也不自动迁移或导入19191/19194/19195的隔离数据。已有APL_STUDIO_DATA覆盖仍保留供隔离测试，普通启动无需设置；若终端之前设过该变量，确认终端打印的数据路径，想使用工程默认库可新开干净终端。

公网部署使用HTTPS域名及部署级访问账号，完整配置、Docker Compose和Nginx示例见[公网部署](deploy/README.md)。API、下载和WebSocket使用同一域名，支持HTTPS反向代理；当前是共享工作区，不提供多用户数据隔离。

开发时分别运行 `npm run dev`、`npm run dev:web`；Vite 页面 http://127.0.0.1:5174 代理 API / WebSocket。服务托管已构建页面，用 `npm run build:web` 更新。

## 使用流程

1. 打开“源码模板”，选择 AP 或灯控，点击“用此模板创建产品”。空白产品也可在概览绑定模板。
2. 编辑产品名称、标识、品类、SDK 版本。模板按精确版本绑定，应用前说明草稿规范化与不支持项目的移除。
3. 在“功能定义”选择能力与默认值，在“产品参数”配置数值、查看需要移植的硬件接口。
4. 保存产品修订；未保存草稿不能用于生成，过期修订返回冲突并保留草稿。
5. 在“交付中心”预览实际文件，点击“生成并验证 SDK”。服务固定产品与源码快照，编译真实 C 库和移植示例，并执行模板消费程序。
6. 两项检查通过后下载 ZIP。失败保留诊断，旧成功归档仍可下载。
7. 工程师将 SDK 加入 MCU 工程，在自己的应用目录实现硬件回调。重新生成仅产生归档，不覆盖用户工程。

产品内“仿真台”运行实际生成的 C 业务程序，支持 AP 文字面板、短按/长按、环境输入、实际负载、暂停/单步/快进、模拟上掉电和会话内存储。“模型预览”保留数据类型检查。详情见 [Web 仿真台](docs/Web仿真台.md)。目标 MCU 与硬件移植仍需工程师验收。

## 已实现

- 多产品管理；布尔、整数、枚举、字符串功能及权限、默认值和约束；SQLite 持久化与修订。
- 模板描述驱动的能力、参数、依赖、移植接口和文件预览。新增普通参数无需改 React。
- `apl.air-care@0.1.0` 与 `@0.1.1`：根APL版本快照，均支持净化加湿、仅净化、仅加湿；0.1.1接入纯净化自动档修复，旧绑定不自动升级。
- `standard.lighting@1.0.0`：独立 C11 灯控示例，电源、亮度和开灯延迟，独立目录及 API。
- 构建队列、真实 C11 编译与消费执行、诊断、历史交付和 ZIP 文件哈希。
- Web 仿真台：独立 C 进程、虚拟时钟、面板手势、传感器输入、实际输出回调、通用运行信息槽位与事件。
- JSON 导入导出与定义包。定义包标记 `sdkReady: false`，验证通过的源码 SDK 标记 `sdkReady: true`。
- WebSocket 变更通知、重连、Ctrl+S、草稿保护与移动端布局。

目前没有共享能力目录、MCP、个人账户、多租户或任意芯片工程生成；公网模式提供一个部署级访问账号。仿真支持 AP 与灯控的已接入版本，新增产品族需要自己的 C 宿主桥接。后续仿真功能统一在 Web 推进；[simulator](../simulator/README.md) 内旧 Qt 工具保留作历史参考，不再继续功能开发。

## 目录与技术栈

沿用 ProbeStation 的 Node.js / TypeScript、React 18、Vite 6、Fastify 5、Cordis、schemastery 与 npm workspaces，版本由 package-lock.json 锁定。

| 目录 | 职责 |
|---|---|
| apps/server / apps/web | 本地服务与产品工作台 |
| packages/model | 产品与模板描述、共用校验 |
| packages/product | SQLite 产品与修订 |
| packages/templates | 注册、AP 专用生成器、通用 C 生成器 |
| packages/build | SDK 构建归档、仿真会话与 C 宿主桥接 |
| packages/api / packages/definition | HTTP / WebSocket 与定义 ZIP |
| ../apl_sdk_template | 独立的版本化产品源码模板 |
| docs / tests | 规范与无硬件回归 |

## 设置与数据

- `APL_STUDIO_DATA`：默认 .data，包含 studio.db 和 sdk/<任务 UUID>/，停服后备份整个目录。
- `APL_STUDIO_HOST`、`APL_STUDIO_PORT`：缺省127.0.0.1和9190；Vite开发代理默认仍使用9190。
- `APL_STUDIO_PUBLIC_URL`：公网浏览器访问的HTTP(S) origin；公网监听需设置精确公开地址。
- `APL_STUDIO_USERNAME`、`APL_STUDIO_PASSWORD`：部署级访问账号，公网配置时必须成对设置；本地可选。网页、API、下载和WebSocket均受保护。
- `APL_STUDIO_TEMPLATES`：默认相邻的 apl_sdk_template，启动时加载；发布新版本后重启。
- `APL_STUDIO_CC`：本机编译器路径，其次读取 CC。Windows 检测已有 C:/Qt/Tools/mingw1310_64/bin/gcc.exe，否则使用 PATH 中的 gcc；不依赖 Qt 界面或 Qt 库。

编译器仅在服务端配置，网页不接受任意源码或执行命令。模板属于服务端受信任源码，仿真与生成在服务器执行。公网使用HTTPS和部署级访问账号；若需要多个团队分别保管数据，应部署各自的数据目录和服务实例。
