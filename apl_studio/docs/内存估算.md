# 内存估算

在“配置产品 → 芯片与固件裁剪 → 内存估算”中查看RAM预算和Flash记录。估算随产品及裁剪设置更新，主要用于比较方案、发现明显超限和提示缺失输入；不能代替芯片工程的完整链接报告或运行时栈验证。

## 使用步骤

1. 选择目标平台，填写芯片可用于当前预算的RAM、Flash容量及软件栈预留。
2. 选择裁剪预设或自定义编译开关。C51平台会按当前头文件的预留规则计算APL实例大小；通用C平台需要填写目标编译器测得的单实例`sizeof(struct apl)`。
3. 填写实例数量、宿主及其他静态数据、安全余量。尚不清楚其他静态数据时保持未填写；只有确认不占用该项时才填写0。
4. 如已有目标链接结果，可填写Flash已用字节；没有结果时保持未填写，不将缺失值当成0。
5. 保存产品后导出估算记录，或在源码ZIP中的`memory-estimate.json`查看与产品修订和源码指纹关联的同一份预算。

估算设置保存在可选的`firmware_build.memory`中，随产品修订保存，不属于设备运行参数表，不会写入`apl_profile`或运行记忆。

## 输入含义

| 设置 | 缺省值 | 含义 |
|---|---:|---|
| 实例数量 `instanceCount` | 1 | 同时保留的完整APL实例数量 |
| 其他静态数据 `hostStaticBytes` | 未填写 | 宿主及不在APL实例内的常驻数据；0是明确输入，不表示未知 |
| 安全余量 `safetyBytes` | 64 B | 额外保留的预算，可按项目修改；不是编译器测得的占用 |
| 单实例字节 `instanceBytes` | 未填写 | 通用平台下由目标编译器测得的`sizeof(struct apl)`；C51使用头文件参考规则，不以此值覆盖 |
| Flash已用字节 `flashUsedBytes` | 未填写 | 从目标工程链接结果手工记录的总Flash占用；工具未自动验证其来源和新鲜度 |

栈预留继续使用已有`firmware_build.stackBytes`，缺省256 B；不会因为根入口栈帧较小而自动缩减。界面切换平台、芯片型号或编译开关时会清空手填单实例大小和Flash记录；其他数据及余量保留。编译器、优化等级、产品配置或源码变化后，仍应重新核对所有手工输入。

## RAM计算与状态

预算合计为：

`单实例大小 × 实例数量 + 宿主及其他静态数据 + 软件栈预留 + 安全余量`

安全余量计入预算，但不是当前已使用的RAM。未知项不会按0补成一个“完整合计”；界面可以显示已知小计和仍缺少的输入。

| 状态 | 条件与解释 |
|---|---|
| 信息不完整 | 单实例大小或其他静态数据未填写，且已知小计尚未超限 |
| 超出预算 | 完整合计超限，或即使忽略未知项、已知小计也已经超限 |
| 余量较小 | 输入完整，剩余预算不大于总RAM预算的10%；刚好占满也属于此状态 |
| 预算内 | 输入完整且剩余大于10%；只说明当前填写的预算关系，不表示芯片验收通过 |

例如C51全功能实例516 B，其他静态数据479 B，栈256 B、安全余量0 B时，合计1251 B；对1 KB预算，超出227 B。其他静态数据未知时，即使APL实例和栈加起来未超限，也不能据此判定整机放得下。

## C51参考值的边界

C51分项按当前头文件的实例预留计算，包含主控、可选HMI和1字节调度余数。它统计实际对外分配的占位大小，不把私有状态字节数代替实例大小，也不假设每个功能开关都会带来RAM缩减。净化/加湿、各模块和传感器、定时、滤网、产测、睡眠、风干、氛围灯、组合键、自定义回调、蜂鸣器及缓存的影响，以当前分组预留公式为准；记忆关闭主要减少代码，不强行扣除共用状态。共享数据在最后一个使用者关闭时才释放。

APL实例中已经包含主控持有的产品配置副本和HMI持有的快照，不应再重复加一份作为实例开销。以下项目不在该实例数值中：

- 宿主在RAM中持有的回调函数表和上下文、设备驱动状态、UART收发缓冲、触摸和显示缓冲、传感器缓存。
- 宿主另外保留的参数表、运行记忆、快照及Flash写入暂存副本；Flash中的数据不直接计为RAM，但其RAM暂存应计入。
- 实例以外的库共享表、常量表或编译器生成数据，其存储位置必须以目标工程链接结果确认。不能仅凭C的`const`声明就假定不占RAM。
- 临时局部变量、初始化时的产品参数临时表、记忆通知时的临时记忆结构，以及嵌套调用、回调和中断需要的栈。

前三类需要按实际存储位置纳入其他静态数据。临时局部变量应纳入调用链的峰值栈预算，不应既计为常驻数据又重复计入栈；如果宿主将副本长期保存为全局对象，则应计为静态数据。

Keil C51 LARGE使用的XDATA软件栈与IRAM中的硬件栈、ISR寄存器保存不是同一个空间。页面的RAM总预算只适用于用户选定的同一内存池；例如按XDATA预算填写时，仍须单独验证IRAM、DATA/IDATA、硬件栈和中断嵌套，不能将不同内存空间的剩余字节相互抵扣。实例实际放在哪个空间，也应由宿主声明和链接报告确认。

## Flash与交付记录

本功能不按功能开关给Flash随意分配权重，也不把主机程序大小或隔离探针CODE当成完整固件体积。Flash未填写时显示未知；填写后仅计算已填值与预算的差额，并标明为手工记录。链接器删除、库函数、驱动、启动代码和优化选项都会影响最终体积。

独立JSON记录和源码包内的`memory-estimate.json`用于保留估算输入、结果、产品修订与源码来源；它们不是`.M51`或`.MAP`的替代品，也不表示工具已经验证实际目标容量。实际交付仍需用相同宏完整重编译，核对各内存空间的最终链接占用，并验证最坏调用链和中断条件下的栈余量。

## 接口与验证

`GET /api/products/:id/memory-estimate.json?revision=N`返回已保存精确修订的预算记录，过期修订返回409；无效配置和过期源码绑定不能导出。估算设置是可选扩展，原有未带memory的产品按缺省设置显示，不静默改写历史修订。

内部按键映射编入时增加18 B（主控参数表15 B、人机借用指针3 B）；`APL_HMI_COMPILE_KEYMAP=0`可移除此增量，纯主控构建不计入。宿主另存的参数表副本仍需单独计入其他静态数据。

测试覆盖空值与0、超限/恰好占满/余量较小、多实例、不同裁剪、通用平台手填值、严格配置校验、保存修订及JSON/ZIP一致性。另用本机Keil C51对多种构建即时编译sizeof探针核对模型；该测试不链接整机。未安装Keil时该项会明确跳过，不用GCC结果冒充C51验证。
