# Web 仿真台

## 使用

在产品内选择“仿真台”。绑定支持的模板，保存功能与参数，再点击“启动仿真”。当前支持 `apl.air-care@0.1.0` 与 `standard.lighting@1.0.0`。

页面上方的“面板样式”可随时切换外观：AP 支持“圆形面板 / 按键台”，灯控支持“卡片面板 / 紧凑控制台”。切换共用当前 C 会话，不重启、不编译，不清空时钟、事件或存储。样式按产品保存在当前浏览器中，重新进入时恢复；它不属于产品配置，也不影响 SDK。浏览器禁用本地存储时仍可切换，只是不记住选择。

启动时从该产品修订生成真实 C 源码，使用本机 GCC 兼容 C11 编译器编译业务源码和宿主桥接，启动一个独立进程。编译器沿用 `APL_STUDIO_CC` / `CC` 和本机 GCC 检测。每次按键、读写和推进时间直接操作这个进程，不需要重新编译 Studio。配置保存后点击“重新启动”才应用到新会话。

- AP：Purify、Humidity、Timer、Light、Speed、Power 文字按键；点击主体短按，点击下方“长按 3 秒”发送长按。按钮支持 Tab 与 Enter / 空格操作。
- AP 按键注入电平，经实际 HMI 扫描识别手势。短按推进 70 ms，长按推进 3070 ms；长按到时发出一次，松开不再补短按。禁用能力对应的键不显示；童锁等规则由 C 库判断。当前未提供组合键同时按住输入。
- 环境输入：湿度、PM2.5、水位、UV 安全开关，按模板能力显示。数字修改后点击“应用”。业务代码按自己的采样周期读取输入，传感器的注入值与运行信息中的采样值可能暂时不同。
- 灯控：设置开灯请求与亮度，观察启动延迟结束后实际输出回调发生的变化。
- 自动运行每次推进 100 ms 虚拟时间。暂停后可以单步 10 ms、快进 1 秒或 1 分钟。时间推进只调用 C tick，不用页面逻辑推算业务结果；暂停后按键仍推进该手势需要的虚拟时间。
- “模拟掉电”切断模拟负载并停止调用设备 tick；“模拟上电”重新初始化设备。它们与面板 Power 键不同：Power 键按 C 逻辑可能进入关机风干。
- “重置设备与存储”清空模拟存储、归零虚拟时钟，再按产品配置重新上电。
- 停止会话或离开仿真台释放进程。重新进入需要启动新会话；停止后页面显示最后快照，不能继续操作。

## 显示与事件

“实际负载”来自 C 注入的硬件输出回调。AP 显示风机及输出档位、加湿负载、UV、负离子与蜂鸣器；灯控显示灯光使能和实际亮度。网页不会根据按键名称直接设置这些值。

AP 数码管来自 HMI 的字符、单位和亮度 getter，上电时显示 888；面板显示、童锁与业务状态来自 C 快照。运行信息使用通用槽位，仿真适配器声明名称、单位和枚举，网页显示未知槽位时回退到字段 key。

事件分为输入、负载、状态、系统和存储：

- `Light短按` 表示 C HMI 接受了一次手势；随后若灯光 getter 变化，记录 `面板灯光 → 开/关`。如果触摸只唤醒屏幕而未改变灯光，则不制造灯光开关事件。
- 被童锁或功能规则忽略的输入记录为“输入，未被面板接受”。
- 输出回调发生改变时立即记录负载事件，快进中的蜂鸣器开关也保留。
- 命名的显示和内部状态槽位按每次回复的快照比较，记录前后变化；快速闪烁的完整灯字节可在原始快照中查看，不逐拍记录图标。
- 显示最近 300 条，支持筛选、清空当前显示与 JSON 导出。导出包含产品修订、模板和桥接指纹。虚拟时间重置后事件序号仍递增。

页面每 250 ms 读取会话，实时自动推进在服务端进行；自动 tick 与用户操作串行执行。精确检查边界时请先暂停。仿真用于逻辑验证，硬件移植仍由工程师在目标 MCU 上完成。

## 掉电记忆

AP 宿主在 `memory_save` 回调内保存记录，上电初始化后、第一拍之前调用 `apl_core_memory_restore` 交回。存储器不自行决定 APL 要保存哪些字段。掉电前正在运行可恢复，风干与待机等情况由库自己的存储策略决定。

记忆仅在本次进程/会话内保留；停止、离开页面或服务重启后不恢复。灯控模板未声明记忆接口，上电恢复配置默认值。不要把仿真会话存储当成设备闪存格式。

## 服务接口

| 请求 | 用途 |
|---|---|
| GET `/api/products/:id/simulation` | 当前已保存产品的仿真描述；不支持时 descriptor 为 null |
| POST `/api/simulation/sessions` | `{ productId, revision, running?: boolean }`，精确修订，返回 202 会话 |
| GET `/api/simulation/sessions/:id` | 状态、快照、槽位描述、事件、编译诊断 |
| POST `/api/simulation/sessions/:id/actions` | 执行一次操作，返回最新会话 |
| DELETE `/api/simulation/sessions/:id` | 停止并释放进程 |

操作示例：

```json
{ "type": "running", "value": false }
{ "type": "advance", "ms": 1000 }
{ "type": "input", "key": "Light", "value": "short" }
{ "type": "input", "key": "Power", "value": "long" }
{ "type": "input", "key": "water_level", "value": 0 }
{ "type": "input", "key": "power", "value": true }
{ "type": "supply", "on": false }
{ "type": "reset" }
```

每次推进 10–60000 ms，10 ms 步进；输入严格按会话能力、类型和范围检查。仿真最多同时四个会话；两分钟没有读取或操作自动停止。服务重启不恢复旧会话。源码及产品快照在 `.data/simulation/<UUID>/` 留作诊断，不作为 SDK 交付物。

## 接入其他产品

共用模型在 `packages/model/src/simulation.ts`。`packages/build/src/simulation-adapters.ts` 注册每个产品族的 `SimulationAdapter`：

1. 精确声明支持的模板引擎、版本或 API 兼容范围。
2. `describe` 给出输入控件、输出和运行信息槽位，按产品已启用能力过滤。
3. 声明实际业务源码目录与头文件目录。
4. 提供 C 宿主桥接：初始化、tick、模拟输入、上下电、快照和可选记忆回调。
5. 给输入配置私有整数编号；服务仅发送预先校验的编号与整数，不接收浏览器脚本、任意 C 源码或命令。
6. 加入真实编译、执行和隔离测试。

现有 C 协议由 `runners/common.c` 管理，逐行 JSON 返回事件和关联请求号的快照。输入命令与输出协议是内部实现，不属于嵌入式 SDK ABI。新增产品适配器仍需编写桥接，平台不会仅根据功能 key 自动推断业务。

模板版本仍按冻结目录使用，现有 SDK 源码模板没有因仿真而改写；仿真桥接在平台内单独维护和计算指纹。SDK 与仿真调用同一模板生成器、同一配置、同一业务 C 源码，硬件回调分别由 MCU 移植层或仿真宿主提供。
