# 产品定义与接口 · v1

## 数据模型

产品记录由平台管理，包含 UUID `id`、递增 `revision`、`createdAt`、`updatedAt` 和 `definition`。时间使用 ISO 8601 UTC。导入 / 导出的产品定义不包含平台记录元数据。

`definition` 包含且仅包含：

| 字段 | 说明 |
|---|---|
| schemaVersion | 当前为整数 1 |
| name | 产品名，1–80 字，不换行 |
| code | 工作区唯一标识，小写字母开头，后续为小写字母、数字、下划线，最多 48 位 |
| description | 产品说明，最多 2000 字 |
| category | 产品品类，1–40 字 |
| sdkVersion | 主版本.次版本.修订号，例如 0.1.0；这是目标 SDK 版本，不是已经产生的 SDK |
| functions | 有序功能定义数组 |
| parameters | 有序产品参数数组 |
| template | 未绑定为 null，绑定精确引用为 `{ id, version }` |

标识不能是 C 关键字。未知格式和字段报错，不会在保存时静默丢弃。

功能字段：`id`、`key`、`name`、`description`、`kind`、`access`、`default`、`unit`、`min`、`max`、`step`、`maxLength`、`options`。

- `id` 是功能的稳定内部标识；`key` 是产品内唯一的接口标识。
- `kind`：bool / int / enum / string。
- `access`：read / write / readwrite。
- int 的 min/max/default 为有符号 32 位整数；step 为正整数。默认值必须位于范围内且落在从 min 开始的步进上。
- enum 的 options 为 `{ label, value }` 数组；非空，数值是不同的有符号 32 位整数，default 必须命中选项。
- string 的 maxLength 为 1–4096 个 JavaScript 字符单位，default 不含空字符。字符串接口的传输编码与业务含义需在后续模板中明确。
- 所有功能都保留范围、字符串长度和 options 元数据。切换类型时编辑器清理不适用的旧选项；服务端仍校验元数据完整性。

参数字段为 `id`、`key`、`name`、`value`；值支持布尔、有符号 32 位整数和文本。未绑定时参数作为定义交付；绑定模板后按描述校验类型、范围、依赖，并通过显式 binding 映射到配置宏。

## 接口契约预览

接口前缀为 `apl_<产品标识>`，例如：

```c
bool apl_air_care_get_power(void);
bool apl_air_care_set_power(bool value);
int32_t apl_air_care_get_humidity(void);
size_t apl_air_care_get_label(char *buffer, size_t capacity);
```

只读功能不生成 setter，只写功能不生成 getter。枚举生成产品作用域的 C enum；字符串通过调用者提供的缓冲区交换。

以上是未绑定产品的声明预览。绑定后展示模板实际生成的接口：AP 使用 apl_<code>_t *self，灯控使用 sdk_<code>_t *self。下载包头文件是实际 ABI，模板说明生命周期、错误和状态语义。

## 保存一致性

创建产品写入 r1；每次更新必须提交当前 revision，成功后增加一版。更新和修订快照在一个 SQLite 事务内提交。
旧版本保存或删除返回 409，不覆盖其他窗口的更改。WebSocket 通知不会直接覆盖草稿，界面提示用户读取最新版。

交付中心的整包导出只读取已保存的修订，未保存时禁用导出；单文件预览下载可包含当前草稿，并按草稿标记。

定义包路径固定，不使用用户名称生成内部路径。manifest 记录包类型、平台版本、产品 ID、修订、目标 SDK 版本、各文件 SHA-256 和文件集指纹，并明确 `sdkReady: false`。manifest 自身不参与文件集指纹。

## HTTP

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | /health | 服务存活 |
| GET | /api/system | 平台版本及真实能力标志 |
| GET / POST | /api/products | 产品列表 / 新建，POST 请求体是 definition |
| GET | /api/products/:id | 读取产品记录 |
| PUT | /api/products/:id | `{ revision, definition }`，更新产品 |
| DELETE | /api/products/:id | `{ revision }`，删除产品及修订 |
| GET | /api/products/:id/revisions | 修订号与保存时间 |
| GET | /api/products/:id/definition | 导出可重新导入的 JSON |
| GET | /api/products/:id/export | 下载已保存修订的定义 ZIP |
| POST | /api/definitions/validate | 校验 definition，返回 issues |
| POST | /api/definitions/interface | 从有效 definition 生成接口文本 |
| GET | /api/templates | 可用模板完整描述列表 |
| POST | /api/templates/:id/:version/configure | { definition }，返回规范化候选，不保存 |
| POST | /api/templates/preview | { definition }，模板声明的实际生成文件 |
| POST | /api/sdk/generate | { productId, revision }，202返回任务 |
| GET | /api/products/:id/sdk/jobs | 产品历史构建 |
| GET | /api/sdk/jobs/:id | 状态、阶段、编译与消费结果、诊断 |
| GET | /api/sdk/jobs/:id/download | 成功返回SDK ZIP，未通过返回409 |
| GET | /api/products/:id/simulation | 已保存产品的仿真控件与槽位描述 |
| POST | /api/simulation/sessions | { productId, revision, running? }，202 返回 C 仿真会话 |

## SDK 构建一致性

任务固定产品修订、模板版本和源码指纹，记录源码版本、验证范围、时间、状态、阶段与诊断。checks.compile 和 checks.consumer 均 passed 后才能下载，SDK manifest 标记 sdkReady 为 true。

生成请求的修订过期返回409 / REVISION_CONFLICT。排队后更新产品不改变原任务，历史归档仍可下载。重启恢复任务记录，未完成任务标记失败并要求重新生成。WebSocket 的 sdk/changed 推送任务快照。

## 仿真一致性

仿真固定已保存的产品修订、模板指纹和 C 桥接指纹。与 SDK 使用同一模板生成器及业务源码，设备实例和环境输入相互隔离；修改配置后需要重新启动会话。未保存草稿不能启动仿真。会话数据通过 HTTP 轮询，仿真 tick 在服务端推进；停止后仅保留最后快照。具体操作、事件语义和模板桥接说明见 [Web 仿真台](Web仿真台.md)。
