# APL Studio 按键动作映射

Studio 配置的是 **APL 收到某个输入后执行什么动作**。GPIO、触摸通道、扫描消抖以及宿主如何填写 `apl_hmi_key_state` 仍由宿主工程负责，输入编号保持不变。

例如，把 `Light` 输入的短按设成“电源开关”，宿主仍向 `light` 提交按下、松开；APL 将识别出的短按解释为开关机。仿真仍发送 `Light`，输入事件仍记录 `Light` 短按，随后实际状态或输出发生变化时再记录相应事件。

## 配置流程

1. 打开产品的“配置产品”页面，在“按键动作映射”开启“启用自定义按键动作”。
2. 按输入槽位分别选择短按、长按动作。名称后面的 `Light · 3` 等标识是宿主输入身份。
3. 保存后进入仿真，使用原输入位置测试新动作，包括待机、运行、熄屏和童锁状态。
4. 导出参数表或当前产品的 C 源码包，把同一份参数交给宿主。

关闭自定义映射保留编辑过的选择，但恢复标准行为。“恢复标准映射”同时关闭自定义映射并把两组动作恢复为标准值。

## 输入槽位与标准行为

| 编号 | 输入 | 短按 | 长按 3 秒 |
|---|---|---|---|
| 0 | Purify | 净化复合开关 | Wi-Fi 配网 |
| 1 | Humidity | 标准加湿 / 恒湿操作 | 标准恒湿编辑 |
| 2 | Timer | 设置定时 | 童锁开关 |
| 3 | Light | 灯光开关 | 无动作 |
| 4 | Speed | 切换风档 | 极速开关 |
| 5 | Power | 电源开关 | 停止关机风干 |
| 6 | Filter | 查询滤芯 | 复位并查询滤芯 |

标准行为仍受产品能力和当前状态限制。例如，纯净化使用滤芯输入，一体机与纯加湿的湿度操作不同；Wi-Fi 未启用时不执行配网。关闭自定义映射时完全沿用原面板策略。

动作还包括“睡眠开关”和“加湿开关”。其中“加湿开关”只切换加湿，与保留机型差异和恒湿编辑的“加湿 / 恒湿”不同。

“无动作”不会执行业务操作，也不会唤醒显示。它占据一个明确的动作槽位，不表示回退到该输入原有功能。启用自定义映射后，短按和长按的 14 个槽位全部由表决定。

建议保留一个可操作的电源动作；使用童锁时，也保留能够解除童锁的动作。动作仍受运行状态检查，不会因为换到另一个输入而绕过状态规则。

## 裁剪与暂不可用动作

- 输入槽位被裁剪后，对应两项选择不可修改，已保存的动作仍保留。重新编入该输入后可继续使用。
- 对应业务未启用或已裁剪时，动作显示“当前未启用”。已有选择可以保留，当前不会执行；功能恢复后继续使用该选择。
- 自定义映射依赖 `APL_COMPILE_HMI=1` 和 `APL_HMI_COMPILE_KEYMAP=1`。关闭其中任一项时，不能保存一份仍启用自定义映射的产品。点击“恢复标准映射”关闭它，或重新编入所需功能。
- 裁掉整个 HMI 后，由宿主自行处理按键；裁掉映射但保留 HMI 时，使用标准映射。

映射不修改组合键。标准组合仍是原始输入 `Timer + Speed` 复位滤网、`Power + Timer` 进入产测，保持 3 秒；是否可用还取决于组合键槽位、输入和对应业务是否编入。重映射电源或定时动作不会移动这些组合。

## 参数和版本

当前映射属于参数格式 **v6**。Studio 在产品参数中使用一个可选的 `key_mapping` 字符串保存结构化 JSON；旧产品没有该项时按标准映射解释。

```json
{
  "enabled": false,
  "short": [5, 10, 7, 9, 3, 1, 12],
  "long": [6, 11, 8, 0, 4, 2, 13]
}
```

两组数组必须各有 7 项，按上表输入编号排序；动作编号为 0～15。动作编号、C 枚举及完整含义见 [APL 按键映射契约](../../apl_lib/按键映射.md)。动作名称用于界面阅读，编号用于保存和生成 C 初始化代码。

参数表和 C 源码包由同一份已保存产品配置生成。Excel 和此 JSON 都不是既定串口报文；串口协议和寄存器映射应另行定义。不能将 `struct apl_profile` 的内存字节直接发送给芯片，也不能用 v6 结构解释历史版本参数。

## 内存成本

按 Keil C51 LARGE 的当前布局，编入自定义映射增加 **18 B 实例静态空间**：主控保存的配置表增加 15 B，HMI 借用该表的指针增加 3 B。关闭 `APL_HMI_COMPILE_KEYMAP` 后这些实例字段和映射执行代码一同裁剪。其他平台的指针对齐与大小应以实际编译结果为准。

宿主另行保留的配置副本也要计算空间：每份含映射的 `struct apl_profile` 再增加 15 B。Flash 占用、调用栈和最终芯片 RAM 是否足够，仍需使用完整宿主工程的链接结果判断。
