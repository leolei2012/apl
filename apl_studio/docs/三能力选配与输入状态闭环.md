# 三能力选配与输入状态闭环（本地0.4.0）

模板 `apl.air-care@0.4.0`，根业务源 `0.2.0`（f69f552），工作流 `air-care-standard-v2`。模板版本与业务版本分别记录；旧0.1.0/0.1.1/0.2.0/0.3.0不修改，真实产品绑定不迁移。开发源仍只在 `apl_lib` 维护。

## 已实现及规范依据

| 内容 | 工作簿位置 | 确定行为 |
| --- | --- | --- |
| 定时长按连增 | 更改记录D21:D22、加湿器E7、一体机E7 | 设置中1.5秒后每0.5秒加一，过零停2秒；松手3秒确认；设置外3秒长按仍为童锁。到期经普通关机决定风干。 |
| 睡眠独立计时 | 净化器H10、加湿器G10、一体机G10、更改记录D23 | 独立5秒熄屏，设置/查询仍为3秒；电源直接执行，其他键首次仅唤醒。灯位冲突不变。 |
| 面板维护与极速灯 | 按键说明C9:J12、净化器极速条目 | 纯净化独立FILTER支持待机查询/重置；加湿/一体机用定时+风速；极速三档灯同亮。 |
| 独立模块 | 净化器D14:H15、一体机C14:G15、目录A15:D18 | UV/负离子/Wi-Fi独立选配；UV/负离子独立请求，复合键保留；缺失/非法UV联锁禁用输出。 |
| 输入状态和故障 | 三机型开机/Auto行、错误代码B3/K3/H11:L11、多传感器表 | ABSENT/WARMUP/VALID/FAULT，预处理/故障不读数值；PM故障E9、预处理“ --”；湿度故障不伪造正常湿度。 |

输入状态和模块故障由宿主缓存的真实驱动结果提供，测试注入的是契约状态；**没有实现传感器通信超时、开短路持续时间或真实负载故障检测器**。NULL状态回调仅为旧宿主兼容；新port明确返回ABSENT。RH无效时停止恒湿泵，保留目标；CO策略和三个湿度争议不变。备用档缺省2仅延续旧纯加湿默认，项目须确认；预处理沿用开机物理档。传感器单位为PM2.5/PM10/HCHO/TVOC整数μg/m³，RH整数百分比。

## Web与可复现验证

在新方案目录显式选择0.4.0。产品类型、UV/负离子/Wi-Fi、PM2.5/RH和三个辅助输入由表单选择；能力依赖与备用档写入实际C配置。高级输入体验使用独立原生桥，不依赖暂停的组合键开发文件。虚拟组合输入只模拟按下/释放普通键，不证明触摸硬件支持多键。

```powershell
cd apl_studio
$env:CC='C:/Qt/Tools/mingw1310_64/bin/gcc.exe'
npm run typecheck
npm run build:web
node --import tsx --test tests/advanced-workflow.test.ts
```

五配置真实C场景：纯净化21、纯加湿20、一体23、全选配32、无选配9项；同一生成源再运行GCC消费者。报告绑定产品修订/定义、模板、生成文件和原生桥指纹，源变化使报告过期。交付包含中文功能/验收/工程清单与验收JSON。

本轮生成诊断SDK通过模板 `generate()` 直接写入隔离目录，再做GCC和C51消费；没有执行浏览器或HTTP下载，也没有替代此前用户取消的浏览器下载动作。诊断manifest标注 `apl-source-validation-v1`，不是服务器正式归档下载凭据。正式归档仍走已有验收门禁与SDK构建；本轮未再次验证下载步骤。

## 平台与边界

C51公开头、库及回调使用配对APL_CALL/LARGE reentrant；版本0.2.0新增ops/快照/记忆字段，不能把0.1.x旧原始结构体当新布局直接读取。NVM需独立版本、逐字段编码、校验和掉电原子性。启动时软件栈必须初始化并预留XDATA；测试链接不能替代实际ISR、栈高水位和10ms时序。

三项湿度冲突、1/3小时风干与历史窗口、灯位、E1/E2、TVOC/HCHO边界、精确水位/水箱到位、首次记忆及2199/2200h、产测步骤仍集中待确认，未声称整份Excel全部符合。板间职责/协议、逻辑键与8路TK、数码管段码、PWM/负载反馈、NVM和上板验证仍需真实资料。19191演示与真实数据库未改。
