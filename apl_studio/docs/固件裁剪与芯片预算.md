# 固件裁剪与芯片预算

APL Studio管理两层配置：产品参数决定运行行为，固件裁剪决定哪些代码和私有状态在编译时保留。该能力覆盖各个可选功能，Wi-Fi只是其中一项。运行时不能恢复已经裁掉的实现；修改裁剪后须重新编译并烧录设备固件。

在“配置产品 → 芯片与固件裁剪”中选择平台、填写可选芯片型号及资源预算，选择预设或展开自定义编译开关。

| 预设 | 行为 |
|---|---|
| 全功能 | 保留默认支持能力，产品之间可仅改变运行参数 |
| 按产品裁剪 | 以当前产品功能、模块、传感器及极速选择生成编译条件 |
| 紧凑面板 | 按产品裁剪，并移除每键自定义回调和滤网缓存，最多保留两组标准组合及蜂鸣器 |
| 最小面板 | 进一步去掉组合键和全部蜂鸣提示，包括报警音 |
| 纯主控 | 去掉HMI，宿主自行实现按键、显示及交互策略 |

自定义开关覆盖净化、加湿、UV、负离子、Wi-Fi、各传感器、极速、定时、滤网、产测、运行记忆、睡眠、风干、RGB氛围灯，内部按键映射，以及HMI、蜂鸣器、回调、组合和各逻辑键。条件编译移除对应实现、私有状态和专用API；共用接口和输出槽位可保留稳定编号。详情见[APL编译裁剪](../../docs/规范/APL编译裁剪.md)。

预设按点击时的产品配置生成。以后启用新能力时，如果固件没有编入它，需重新生成兼容裁剪。关闭定时不等于移除Timer键：长按童锁及使用该键的组合操作仍可存在；逻辑键可以单独裁剪。关闭运行记忆只移除读写/通知实现，首次开机所用的共用状态仍保留。加湿与UV保留时，缺水停泵和安全联锁也必须保留。

## 保存及旧配置

裁剪、芯片和预算随产品修订保存。它们以`firmware_build`中的JSON文本持久化，不放入设备运行参数表，也不通过导入Excel动态改变二进制能力。

没有固件设置的旧产品仍按全功能处理。之前的设置缺少新开关（定时、滤网、产测、记忆、睡眠、风干、氛围灯、内部按键映射）时，均按1解释，保持旧行为，不静默改写旧修订。确认当前源码绑定并保存新修订后再仿真/导出。

运行参数仍保留在Studio中，暂时裁掉的字段由生成器按宏保护，不写入已不存在的C成员。逻辑参数格式现为v6（新增内部按键动作映射）；不同裁剪下C结构体物理布局不保证相同，不能用裸结构体传输或烧录。

## 仿真

仿真与源码包使用相同开关，不用全功能实例冒充裁剪结果。相应控件和桥接遵循已编入能力；关闭蜂鸣器时不编入真实播放逻辑。纯主控没有HMI，页面会提示并可继续导出，启动API返回`HMI_COMPILED_OUT`。

Wi-Fi关闭时源集直接省略`src/apl_wifi.c`。其他功能目前在主控/HMI文件内按函数组条件编译，并非每项功能都物理拆成独立源文件。宿主的驱动文件和回调引用由宿主工程自行裁剪；APL不自动删除外设驱动。共用ops槽位、DTO、灯位和图标数组保持稳定，不能按开关数量推断同等比例RAM节省。

选择目标平台不会把本机GCC变成芯片交叉编译器。仿真用于业务和接口验证，不代表目标时序、波形或容量验收。

## 导出

“导出交付”提供Excel参数表、C源码ZIP及内存估算JSON。源码接口为`GET /api/products/:id/firmware.zip?revision=N`，要求已保存的精确修订，拒绝过期修订、源码来源或能力冲突。

源码包包含：

- `src`、`include`、`config`，仓库全功能源码本身不被改写。
- 自动包含的`config/apl_target_config.h`，为全工程提供同一裁剪条件。
- `include/apl_product_profile.h`及`apl_product_profile_defaults`，仅对已编入字段赋产品缺省值。
- `product.apl.json`、`firmware-build.json`、`memory-estimate.json`。
- 来源指纹、产品修订及文件SHA-256清单，明确尚未编译或验收目标容量。
- 宿主接入说明。

所有库源文件和宿主都须采用包内相同头文件和宏，并完整重编译；外部宏冲突会报错。被裁掉的专用API不再提供，不保留空函数；手写宿主代码必须按相同条件保护调用。HMI关闭时不得访问`device.hmi`或调用`apl_hmi_*`。

包含产品默认参数头，调用`apl_product_profile_defaults(&p)`后将`&p`交给`apl_init_profile`，成功后才开始调度；运行记忆仅在其已编入且兼容时恢复。传NULL仍使用库的通用缺省参数，不自动采用本产品所有运行值。传输、存储、联网模块及实际负载由宿主接入。

## 内存和Flash

[内存估算](内存估算.md)按当前条件计算APL分项，再加入实例数量、其他数据、软件栈和安全余量。未知项不按0补齐。C51按同一XDATA预算池计算，IRAM及硬件/中断栈需另行验收；通用平台需要目标`sizeof`。

以下为v5历史Keil C51 LARGE参考，表中仅为APL实例预留，未包含宿主、共享静态表及栈。

| 构建 | 纯净化 | 纯加湿 | 一体机 |
|---|---:|---:|---:|
| 各产品能力的缺省构建 | 443 B | 475 B | 498 B |
| 裁剪参考 | 208 B | 241 B | 242 B |
| 裁剪参考再关闭HMI | 48 B | 69 B | 70 B |

“裁剪参考”关闭新7项功能、蜂鸣器、每键回调、组合键、Wi-Fi、UV、负离子、极速和全部传感器，不等同于页面“最小面板”预设。各产品缺省构建的传感器及UV/负离子按业务能力取默认值。完整测量开关在`output/memory/features-default.json`、`features-minimum.json`和`features-core-minimum.json`。

v6新增内部映射默认编入，含HMI的实例比上述值多18 B；关闭`APL_HMI_COMPILE_KEYMAP`可恢复原容量，纯主控不受影响。内部映射的短按、长按按[按键映射](按键映射.md)配置，宿主绑定不变。

其他组合按当前宏公式计算；关闭共享功能未必独立减少RAM，MEMORY关闭主要节省实现代码。不能沿用旧裁剪表中的固定加减数解释所有新组合。

Flash只记录手填的完整目标链接占用，不按模块随意分配权重，也不把隔离探针CODE当成完整固件。最终使用相同宏完整链接后的`.M51`/`.MAP`核对各内存空间和调用链栈。当前不自动识别芯片、交叉编译或烧录，也不自动判定芯片容量合格。

## 验证入口

此前功能裁剪基线的Studio全套66项测试已在启用C51检查时通过；`tests/firmware.test.ts`及功能裁剪矩阵覆盖配置/能力依赖、旧配置解释、源码包消费和专用符号消失。19种新裁剪组合已完成GCC行为、公开/私有符号及Keil源文件检查，另有22组新sizeof与内存公式一致。原生回归另按实际收据记录；这些检查仍不代替实际芯片工程的完整链接和硬件验证。

## v6 内部按键映射验证

新增 `APL_HMI_COMPILE_KEYMAP`，默认1；关闭后保留标准按键策略。Studio支持独立短按/长按映射，参数格式升级为v6、定义修订7，宿主输入编号及硬件绑定保持不变。

本次 Keil C51 LARGE 实测：纯净化461 B、纯加湿493 B、一体机516 B。这里按各产品编译能力缺省构建；一体机分项为主控192 B、人机323 B、调度1 B。关闭KEYMAP时各含HMI构建减少18 B，纯主控不变。测量收据为 `apl_studio/output/memory/keymap-default.json` 和 `keymap-fixed.json`；这些是隔离编译器对象测量，不是整机链接或栈验证。

139项原生行为回归通过，收据输入哈希与当前C源码一致。Studio全量75项中74项首次通过，剩余1项为旧内存预期322 B未包含映射增量，更新为340 B后单独复测通过；新增9项映射界面、模型、导出和真实C仿真检查另已复测通过。23组新Keil sizeof与估算规则一致，类型检查和Web构建通过。浏览器验证了Light输入映射电源、风机实际开启且事件仍记录Light短按。
