# 源码模板接入约定

平台从版本化描述生成表单与交付流程，业务源码独立于 React、Node.js 和 SQLite。新增普通 C11 模板无需改前端或构建服务。

## 目录与引擎

默认根目录为相邻 apl_sdk_template，布局为 `<产品族>/<主.次.修订>/template.json`。注册键为 id + version；目录版本必须与声明一致，重复版本或未知引擎报错。

- apl-air-care-v1：AP 专用生成器，旧版未声明 engine 时兼容此引擎，补充实际产品接口、移植示例和验证程序。
- native-c-v1：通用 C 模板，自己提供公共 API、实现、移植入口和消费程序，无 APL 或特定品类的强制依赖。

AP 原描述的品类默认值、预览和构建声明由兼容适配器补齐。启动时缓存输入字节并计算 SHA-256，运行中编辑源文件不改变已缓存版本或排队任务。发布更新应新建版本目录并重启。

## 通用字段

| 字段 | 内容 |
|---|---|
| formatVersion / definitionSchemaVersion | 当前均为1 |
| engine | native-c-v1 |
| id / version | 稳定模板 ID 和精确版本 |
| name / description / sourceVersion | 名称、说明、业务源码版本 |
| productDefaults | code、category，用于新建产品；标识冲突增加后缀 |
| features | 完整功能定义、required、enabledByDefault、requires、配置绑定 |
| parameters | int / bool / enum，默认值、范围 / 步进 / 选项、依赖和绑定 |
| ports | 硬件接口名称、C 签名、必需性、说明与能力依赖 |
| constraints | 当前支持 atLeastOne，要求指定能力至少启用一项 |
| directories / staticFiles | 归档的源码目录与其他文件，相对路径 |
| previewFiles | 交付页展示的实际生成文件 |
| verification | 源码目录、包含目录、消费程序与验证范围 |

灯控的构建声明：

```json
{
  "verification": {
    "sourceDirectories": ["lib", "board", "samples"],
    "includeDirectories": ["api", "settings", "board"],
    "consumer": "checks/verify.c",
    "scope": "灯控默认值、开灯延迟、亮度范围、实际输出回调与实例隔离"
  }
}
```

平台固定使用 GCC 兼容 C11 流程，编译声明目录下全部 C 文件和消费程序，开启 Wall / Wextra / Werror，再执行程序。模板不定义 shell 命令，编译器由服务端 APL_STUDIO_CC 设置。

native-c-v1 用于 UTF-8 文本源码，当前不支持任意二进制资产、其他语言或自定义构建命令。

## 配置映射

绑定如 `{ "path": "settings/product_config.h", "macro": "LIGHT_BOOT_DELAY_MS" }`：

- feature.enabledBindings 映射能力是否选中，值为0 / 1。模板保证裁剪后的 API 与 C 实现一致。
- feature.defaultBinding 映射功能数值 / 布尔默认值；字符串不能使用数值宏绑定。
- parameter.binding 映射有效参数的数值 / 布尔值；enum 使用数值。

对应头文件中的宏必须恰好定义一次。重复宏绑定、未知依赖、非法值和缺失配置均报错。新增参数时在新版本描述中添加参数和绑定，并提供相应配置宏与业务验证，前端会自动展示表单。

文本占位符支持 `{{PRODUCT_CODE}}`、`{{API_PREFIX}}`（sdk_ + 产品标识）和 `{{SDK_VERSION}}`，全部来自已校验标识或版本。名称与说明不插入 C，未知占位符报错。

## 文件、验证与交付

拒绝绝对路径、目录穿越、符号链接、设备名和大小写冲突。manifest.json、product.apl.json、metadata/template.json 为保留文件。

构建固定产品修订、模板版本、指纹和源码字节。预览调用同一生成器。排队后修改产品不影响原任务。

两项验证均通过才写最终 ZIP，失败保留诊断，下载返回409，旧成功归档不变。manifest 记录产品、源码、模板版本、文件 SHA-256 和实际覆盖范围，自身不参与文件集哈希。

生成只产生归档，不修改用户嵌入式工程。工程师在自己的目录维护硬件实现。包内实际公共头文件为 SDK ABI，未绑定产品的通用契约仅为声明预览。

## 扩展边界

已有类型的新能力与参数可以由描述驱动。增加新类型、跨字段约束、其他语言、MCU 构建驱动或运行桥接仍需扩展协议和平台；不能凭描述自动实现任意业务。

MCP 后续调用同一产品、模板、构建服务，当前尚未开放。
