# 设计说明

## 目标与边界

仿真器是 APL 的宿主。它持有一份 `struct apl`，注入硬件输入与回调，驱动真实库并显示结果。库不依赖 Python 或终端。

净化、加湿、故障和执行器决策应在 APL 中实现。宿主保留必要的按键业务映射和显示映射；正式 `link_command` / `link_snapshot` 尚未定义，因此当前没有序列化通信协议。

## 文件职责

| 文件 / 对象 | 职责 |
|---|---|
| `panel_sim.py / ensure_dll` | 检查修改时间，调用 MSVC 构建并加载 DLL |
| `panel_sim.py / bind_api` | 声明 ctypes 参数与返回类型 |
| `panel_sim.py / Host` | 持有 `struct apl`、回调与模拟传感器；绑定按键；驱动与发布显示 |
| `tui.py / Panel` | 合并输入源、鼠标命中区域、事件摘要、ANSI 绘制 |
| `tui.py / run` | Win32 控制台事件、时间推进、刷新及恢复终端 |
| `apl.def` | 显式导出宿主调用的 C 接口 |
| `test_tui.py` | 不依赖交互窗口的真实库集成检查 |

## 数据流

```text
鼠标 / 键盘 / 保持开关 → Panel 合并六键电平 → Host.down
传感器控件 → Host 输入值
        ↓
apl_tick：先 apl_core_tick（core ops），再 apl_hmi_tick（key_state_get，短按 / 长按）
        ↓
Host 在回调里调用 core / hmi 接口
        ↓
Host.publish → HMI 显示 setter
        ↓
Panel.render ← getter
```

每拍 `Host.step` 调用 `apl_tick`，其中先 `apl_core_tick` 再 `apl_hmi_tick`，然后 `Host.publish`。显示映射因此可以反映本拍按键回调产生的状态。

## 对象和回调生命周期

`struct apl` 的两个成员用 ctypes 联合体提供占位存储和对齐，容量从 `include/apl_core.h`、`include/apl_hmi.h` 的 `APL_CORE_OPAQUE_SIZE`、`APL_HMI_OPAQUE_SIZE` 读取。宿主不直接解释库内部状态。

`Host` 保留 ops 表、ctypes 回调以及指向自身的上下文引用，防止 C 使用期间被 Python 回收。重置后重新初始化对象并绑定按键回调。新增回调必须同样保留引用。

当前绑定和导出表默认净化、加湿两项均编译。单功能裁剪虽然是 C 库支持的配置，但 Python 宿主仍无条件绑定两套符号，尚未适配该构建方式。

## DLL 构建

使用 MSVC `/std:c11 /utf-8 /W4 /WX /LD` 编译 `src/apl.c`、`src/apl_core.c`、`src/apl_hmi.c`。头文件路径指向 `include` 和 `config`。链接使用 `apl.def`。

产物、对象文件和构建批处理位于系统临时目录的 `apl-emulator`。构建缓存依赖文件修改时间；修改构建逻辑本身不一定触发重建。更新库后应退出旧进程再启动，避免 Windows 锁住 DLL。

新增 C 接口时同步检查导出表、ctypes 签名和头文件布局。当前 Windows x64 构建要求 Python 与 DLL 的位数匹配。

## 输入和时序

按键最终电平是键盘按下集合、保持集合和鼠标按下目标的并集。鼠标命中区域由每次绘制生成；调整面板坐标时必须同时保证命中范围与文字一致。

Windows 输入结构使用联合体读取键盘、鼠标、窗口及焦点事件。`Record` 大小为 20 字节，联合体偏移为 4。终端开启鼠标事件并关闭 Quick Edit，退出时恢复原模式。

TUI 用单调时钟积累时间，以 10 ms 为一拍推进，每轮最多补 20 拍并限制积压；绘制间隔约 50 ms。所有库调用和输入处理在同一线程完成。这是交互仿真，不是硬实时调度，也不保证系统长时间卡顿后完整补齐墙钟时间。

## 面板约定

- 最小窗口为 126 列 × 40 行。
- 六键使用英文名称，按参考面贴位置排布；Light 下方不显示 Sleep (3s)。
- 中央 Sleep 是风机档位，不能与长按标签混为一项。
- 按下状态使用高亮；未点亮或未映射指示使用暗色。
- 保持操作放在面板下方，传感器、状态、事件放在右侧。
- 中央数字、单位、水位、键灯读取 HMI getter；档位和整机状态读取 core getter。

## 扩展和验证

新增业务先明确 APL 规格并实现库接口，再绑定宿主输入、回调与显示。不应仅为了让面板看起来可用而在 Python 中补做控制算法。

修改按键布局后同步调整 `test_tui.py` 中鼠标坐标。改变接口或回调映射后执行 README 中的两条验证命令，并在真实终端核对鼠标按住、键盘松开、童锁、窗口缩小和正常退出。

当前未覆盖：完整产品业务、正式命令和快照、具体组合键绑定、跨平台终端、所有终端的焦点行为与像素级外观一致性。
