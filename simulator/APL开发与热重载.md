# APL 开发与热重载

修改 APL 业务实现后，只构建 APL 动态库。simulator 窗口保持运行，不需要重新构建或重启整个 Qt 程序。

## 开始使用

1. 更新并构建一次 simulator，启动 `workbench/build/apl_workbench.exe`。
2. 工具优先恢复上次选择的源码目录；首次启动从当前目录、程序目录及构建时的工程位置向上查找 APL 工程。
3. 左下角显示“APL 源码 · 自动重载”表示已绑定。鼠标悬停可查看完整路径；也可通过左侧“APL 源码目录”或“产品 → APL 源码目录”选择工程根目录。
4. 工程必须包含 `src`、`include`、`config`，以及现有的三个 APL C 文件、四个公开头和两个配置头。
5. 在编辑器修改业务代码并保存。停止写入约 650 ms 后，工具自动构建并加载新 APL。
6. 要手动重建当前运行配置，使用“产品 → 重新加载 APL”或 Ctrl+B。

自动重载使用最近一次请求应用的产品配置。正常编辑产品页面、保存或打开产品文件都不会自动把草稿应用到仿真；需要显式点击“应用并预览”。若该次应用的 C 代码有错，修正并保存后会重试同一份请求配置。

未发现源码目录时仍可使用随程序内置的 APL；已保存的源码目录失效时明确提示，需重新选择。源码路径与本机编译器路径属于本机工具设置，不写入 `.apl.json` 或交付 SDK。

## 保存、构建与恢复

- 递归读取 `src`、`include`、`config` 下的 `.c`、`.h`、`.inc` 文件，新增文件也会被识别；不跟随目录符号链接。
- 监听文件和目录，并每两秒核对内容，兼容编辑器原子保存、删除后重建文件及分支切换。
- 每次构建先复制源码和配置到独立的临时目录，编译过程不修改原工程。
- 后台只编译 `src` 下的 C 文件和预览专用校验函数，窗口、按键、传感器和旧仿真继续工作；不会调用 CMake 重建 Qt 程序。
- 连续修改会合并；构建完成时再次核对源码。若期间有新版本，丢弃过期结果，再构建最新内容。
- 编译错误、文件缺失、超时、接口不兼容或加载错误都保留原运行实例和上次成功的源码快照。点击页面“查看详情”查看诊断；修复并保存后自动重试。
- 成功替换后按重新上电初始化设备，清除定时、童锁等运行态。传感器输入、通用诊断槽位、文件存储内容及暂停状态保持。
- 构建超时为 120 秒；关闭程序会结束未完成的编译进程。

需要同架构本机 GCC / Clang，选择方法见[产品配置与 SDK 导出](产品配置与SDK导出.md)。不使用 MCU 交叉编译器。

## 配置头的取值

源码目录里的配置头作为模板，保留额外参数、检查和注释；产品配置清单里的宏由产品页面覆盖。
因此，直接修改 `APL_DEFAULT_FAN_GEAR` 等已纳入产品配置的默认宏，不会覆盖页面已选择的值；应在产品页修改并应用。
缺少或重复的已知配置宏会明确报错，避免生成一个与页面不一致的包。新增可视化配置字段仍需同步修改 `ProductConfig`、校验、页面和格式文档。

## SDK 与正在运行的代码保持一致

SDK 导出使用最近一次成功加载的完整文件快照，包含真实源码、生成配置、移植模板和 manifest。
导出时若当前草稿或源码与运行版本不同，会先尝试构建并加载；失败则不导出。
保存 ZIP 对话框打开后固定这份已加载快照，即使源码再次保存，也不会把未经加载的新文件混进包中。

指纹表示文件内容一致，并不代表已经人工验证了全部业务行为。业务效果仍需操作面板和检查实际输出。

## 需要重新构建 simulator 的情况

普通 `.c` 实现、私有头、兼容的额外源文件和配置参数可直接重载。

公开头 `include/apl.h`、`apl_core.h`、`apl_hmi.h`、`apl_type.h` 是宿主与模块共享的接口契约。目前保守比较去掉注释和空白后的内容；公开声明、枚举、宏或结构布局改变时会拒绝加载，提示重新构建 simulator。只修改公开头注释或格式可直接重载。
加载阶段还检查对象 / ops 大小及宿主所需的全部符号，防止拿新回调布局调用旧界面。

修改 Qt / QML 界面、宿主接线、配置字段定义或额外编译依赖，也需要更新 simulator。此流程用于现有 C11 APL，不是通用构建系统；暂不支持自定义链接脚本、额外系统库或 C++ 模块。

## 实现与验证

- `AplSource`：源码目录发现、读取变化通知、防抖与轮询恢复。
- `SdkGenerator`：从实时源码或内嵌回退源生成一次不可变文件集。
- `SdkPreviewJob`：异步本机编译，单次作业、超时及退出清理。
- `WorkbenchWindow`：产品草稿与应用配置分离、过期结果检查、成功快照和导出。
- `AplRuntime`：完整加载后替换接口表；旧库卸载后清理其临时目录。

`workbench --self-test` 在临时源码工程里测试：新增 C / 私有头、实际档位逻辑变化、连续原子保存、构建时界面响应、草稿隔离、编译错误保留旧库、修复恢复、公共接口拒绝、删除重建、构建途中再次保存，以及导出快照隔离。测试不会修改真实 APL 工程。
