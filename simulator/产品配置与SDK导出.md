# 产品配置、仿真和 SDK 导出

## 工具的用途

APL 仿真台负责配置本工程的空气净化 / 加湿库，在内置面板上查看行为，并交付嵌入式源码 SDK。
配置、预览和导出共用同一份产品配置；界面不另写一套业务逻辑。

已经提供：产品新建 / 打开 / 保存、三种机型预设、业务参数和按键裁剪、重新编译预览、ZIP 导出。
当前仍使用工程现有的面板交互规则，不支持任意编辑状态机、引脚自动分配、自定义外设或第三方控制程序。

## 第一次使用

1. 启动 `simulator/workbench/build/apl_workbench.exe`。
2. 选择概览页的“新建产品”，或进入左侧“产品配置”。也可以打开工程内的 `simulator/examples/purifier.apl.json` 示例。
3. 在“产品功能”填写产品名称，选择净化 + 加湿、仅净化或仅加湿；选择默认预览面板。
4. 在“运行参数”设置默认风速、滤芯寿命、风干时间、恒湿回差等，其他参数可点击“更多运行参数”展开。
5. 在“面板按键”选择需要编入的六个按键。未编入的键不会响应短按、长按或参与组合键。
6. 点击“应用并预览”。工具将生成配置头，并用本机编译器重新编译真实 APL C 源码。
7. 页眉状态变为“已应用源码与配置”后，在实时仿真页操作面板、调整传感器并查看事件和固定负载输出。
8. 点击页眉“保存”或按 Ctrl+S，得到 `.apl.json`；以后可重新打开继续配置。
9. 进入“SDK 交付”并点击右上角“导出 SDK”，选择 ZIP 保存位置。交给嵌入式工程师后，按包内 README 完成移植。

编辑和打开配置不会影响运行实例；成功应用配置后重新上电仿真，清除定时、童锁等运行状态，传感器环境值和诊断槽位保留。
仿真时临时切换圆形 / 按键台只是查看方式，配置里的面板选项是下一次应用时的默认视图。

## 需要的本机工具

现有仿真台是 Windows 64 位 Qt / MinGW 构建。预览需要可以生成同架构本机动态库的 GCC 或 Clang C 编译器。
优先使用构建仿真台时的编译器路径，其次查找 PATH 的 gcc / clang；也可在左侧“编译器设置”或“产品 → 本机编译器”指定。
保存配置和查看已有仿真不需要重新编译。

不要在这里选择 ARM 等 MCU 交叉编译器。MCU 编译器用于工程师集成导出的 SDK；仿真预览运行在电脑上。
工具不会自动下载编译器。分发仿真台时，需要同时说明本机编译器依赖。

编译或加载失败会保留原有仿真实例，当前配置仍可保存。页面反馈的“查看详情”可展开编译信息。
编译在后台进行，当前仿真继续运行，成功加载后重新上电，保留暂停状态。编译超时上限为 120 秒，关闭程序会终止构建。源码保存后的自动重载见[APL 开发与热重载](APL开发与热重载.md)。
在当前配置成功编译并加载之前，导出操作会先尝试应用配置，失败则不导出。

“已应用源码与配置”表示编译和加载成功，业务效果仍由使用者通过面板检查。

## 配置范围与校验

| 配置 | 规则 |
|---|---|
| 净化 / 加湿 | 至少包含一项；默认启用的功能必须已包含，至少默认启用一项 |
| 默认风速 | 0 睡眠，1–3 档，4 自动，5 极速；关闭极速支持时不能默认选择极速 |
| 滤芯寿命 | 1–1,000,000 小时 |
| 风干、缺水续运行、缺水闪烁 | 0–86,400 秒 |
| 恒湿回差 | 1–20 个百分点 |
| 产测入口 | 1–3,600 秒 |
| 产测滤芯剩余寿命 | 1–86,400 秒，不得超过完整滤芯寿命 |
| 配网超时 | 1–86,400 秒 |
| CL 显示 | 1–60 秒 |
| 六个按键 | 各自编译或裁剪；也可通过主控命令由外部系统控制 |

这是配置工具当前支持的范围。传感器种类、UV / 负离子独立编译裁剪、目标芯片 GPIO 等尚无对应配置项；
移植层根据 `apl_core_ops` 实现现有输入和输出。PM10 / HCHO / TVOC 仍是可选 ops。

## 导出包内容

```text
apl-sdk/
├── product.apl.json        产品配置，可重新导入工具
├── manifest.json           SDK 版本、生成指纹、逐文件 SHA-256
├── README.md               嵌入式接入说明
├── CMakeLists.txt          通用 C11 静态库构建及移植示例检查
├── include/                APL 公共头文件
├── config/                 生成的两个配置头
├── src/                    APL C 源文件及私有头（含新增文件）
├── port/apl_port.h
├── port/apl_port.c          需要工程师完成的硬件接口模板
└── examples/app.c           初始化和每 10 ms 调用的示例
```

SDK 是源码包，没有 Qt、Windows、RTOS 依赖；功能按生成配置进行编译裁剪，包内保留完整源码。
它不提供某个 MCU 的启动代码、链接脚本、GPIO / PWM / I²C 初始化。
ZIP 使用标准 store 格式，系统解压程序即可打开，不依赖外部压缩工具。

工程师应将移植文件复制到自己的应用目录维护。重新导出的包只替换 APL 源码和配置，保留应用侧移植代码。
工具只写用户选择的产品文件或 ZIP，不会直接覆盖嵌入式工程。

## 确认交付前的效果

建议分别查看上电自检、正常开关机、PM2.5 / 湿度显示、定时确认、灯光和唤醒、童锁、缺水、风干和实际负载输出。
风机状态来自 `set_fan` 的开关与输出档位，不将档位换算成虚构转速；泵来自 `set_pump`。
负载是理想输出模型，不含真实硬件时序和传感器误差。

文件存储方法仍由仿真台提供。当前预览没有自动接上 `memory_save / memory_restore`；
掉电记忆的实际移植需要按 SDK 文档实现、编码和验证存储记录。

## 验证入口

从工程根目录执行：

```powershell
ctest --test-dir simulator/workbench/build --output-on-failure
```

`apl_sdk` 检查配置读写和非法配置、三种机型导出、独立 C 消费程序、预览动态库加载及加载失败保留旧实例。
`workbench` 自检还会实际运行配置编译流程、检查裁剪按键和默认档位，并保存配置窗口截图到系统临时目录的
`apl-product-config.png`。SDK 校验程序可传一个输出目录，保留三种机型的软件包供外部解压检查：

```powershell
simulator/workbench/build/apl_sdk_test.exe simulator/workbench/build/sdk-check
```
