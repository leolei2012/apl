# 产品配置格式与生成设计

## 数据和职责

| 对象 | 职责 |
|---|---|
| ProductConfig | 唯一的产品配置模型、字段清单、校验、JSON 原子读写、配置头生成 |
| ProductEditor / ProductDialog | 嵌入工作区的三个配置页；对话框可复用同一编辑器，只编辑模型 |
| SdkGenerator | 从本地 APL 源码（无目录时回退内嵌源）和移植模板生成文件集、指纹、manifest、目录和 ZIP |
| AplSource | 发现工程、监听源码目录、防抖和变化恢复 |
| SdkPreviewJob | 将不可变文件集写到临时目录，后台调用本机 C 编译器生成 APL 预览库 |
| AplRuntime | 内置 APL 接口表；校验候选库布局与完整符号后切换接口表 |
| AplPlatform | 持有实例，注入固定硬件 ops，推进当前 APL，采集显示和事件 |
| WorkbenchWindow 产品操作 | 配置文件生命周期、保存提示、应用、导出、编译器路径设置 |

生成器的输入是 ProductConfig、本地 APL 工程源码和内嵌移植模板；未绑定源码目录时回退内嵌 APL。递归读取 src/include/config 下的 C、头和 inc 文件，只支持 APL 接口契约。
源文件、模板和配置头仍内嵌作为回退；开发时以绑定目录为准，保存后单独构建 APL，不要求重新构建 Qt 程序。构建时用 COPYONLY 生成资源副本，避免 Qt 将参与编译的 C 源文件标成资源头文件。

## JSON 格式 v1

根对象包含且仅包含以下字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| schemaVersion | 整数，固定为 1 | 产品文件格式版本，与 APL 代码版本独立 |
| name | 字符串 | 产品名，1–80 字符，不能换行；不参与文件路径生成 |
| frontend | `round` / `bench` | 默认仿真视图，不代表 MCU 引脚或新的 HMI 实现 |
| core | 对象 | 核心配置宏对应的整数值 |
| hmi | 对象 | 六个按键编译宏对应的 0 / 1 |

`core` 的完整字段：

```text
APL_COMPILE_PURIFY                 APL_COMPILE_HUMIDIFY
APL_DEFAULT_PURIFY                 APL_DEFAULT_HUMIDIFY
APL_DEFAULT_FAN_GEAR               APL_CORE_DRY_S
APL_CORE_DRY_FAN_GEAR              APL_CORE_FILTER_LIFE_H
APL_CORE_FILTER_SHARED            APL_CORE_WATER_SHORTAGE_RUN_S
APL_CORE_WATER_BLINK_S             APL_CORE_HUMIDITY_HYSTERESIS
APL_CORE_FACTORY_WINDOW_S          APL_CORE_FACTORY_FILTER_LEFT_S
APL_CORE_WIFI_PAIR_S               APL_CORE_FACTORY_CL_S
APL_CORE_HAS_TURBO
```

`hmi` 包含 `APL_HMI_COMPILE_KEY_PURIFY`、`HUMIDITY`、`TIMER`、`LIGHT`、`SPEED`、`POWER`
六个完整宏名。所有值是 JSON 整数；0 / 1 字段也不接受 JSON 布尔值。
所有字段必须齐全，未知字段、字段位置不正确、小数、越界和不支持的版本均报错。
读取失败不修改调用者的已有配置；保存用 QSaveFile 原子替换。

默认值从内嵌的现有配置头提取，字段与范围集中在 `ProductConfig::fields()`。
修改字段或语义时应同步更新格式版本 / 迁移设计、配置 UI 和校验测试，不要静默丢弃旧字段。

## 一致性流程

```text
ProductConfig
    │ 校验
    ▼
SdkGenerator::generate → 相同的 SDK 文件集
    ├── 写临时目录 → 本机 C 编译器 → 校验并加载 → 面板仿真
    └── 写 ZIP → 嵌入式工程使用源码和配置编译
```

配置头以原头文件为模板，只替换清单内的默认宏值，保留头文件保护、编译检查和未开放参数。
生成 API / ops 仍使用 `模块_get_xxx / 模块_set_xxx` 和 `get_xxx / set_xxx` 命名。
仿真库与 SDK 使用完全相同的 `src`、`include` 和 `config`，应用侧不再用 setter 模拟编译裁剪。

指纹是文件集按路径排序后逐项加入路径、零分隔符、内容、零分隔符得到的 SHA-256。
`manifest.json` 自身不参与指纹，避免循环依赖；manifest 记录其余所有文件各自的 SHA-256。
相同输入得到相同 ZIP 内容，不写生成时间。SDK 版本从快照中的 `apl.h` 版本宏读取。

窗口保存最近一次成功加载预览的指纹。编辑后指纹不同，显示待应用；导出前必须重新应用成功。编辑和打开文件不会自动重启预览。
选择不同的编译器本身不改变源码指纹；选择编译器后会重新构建，也可 Ctrl+B 手动重载。
窗口保存成功加载的完整文件快照，导出只使用该快照；保存对话框期间源码再变也不会混入未加载的文件。构建结束核对源文件指纹，过期结果丢弃并构建最新内容。
成功编译不是业务验收记录，manifest 不会宣称已经完成硬件测试。

## 预览库边界

当前使用 GCC / Clang 的 C11 共享库构建参数。只编译快照 src 下的全部 C 文件和一个预览布局校验函数。
该校验函数不进入导出 SDK。编译通过 QProcess 传参数，不使用 shell；产品名称和 JSON 值不成为命令片段。
仿真程序仍有内置 APL，未应用产品时沿用内置实例。

预览构建前比较四个公开头去掉注释与空白后的内容；接口契约变化提示重建 simulator，防止尺寸相同但字段顺序不同的回调被加载。
预览库暴露的是已有 APL C 接口。AplRuntime 要求完整解析宿主需要的接口，并验证 `sizeof(apl)`、
`sizeof(apl_core_ops)`、`sizeof(apl_hmi_ops)`；成功后才替换旧接口表。预览库仅来自本次生成过程，
不能将这项布局校验当作任意第三方二进制的 ABI 兼容保证。

动态库不保存全局 APL 实例，实例仍由 AplPlatform 拥有。后台编译期间时钟继续工作；切换在 UI 线程同步完成，
随后重新初始化并绑定联动。失败保留旧库与旧实例。动态库句柄和临时目录由 AplRuntime 持有，
析构时先卸载库再清理目录，防止 Windows 下已加载 DLL 无法删除。

固定负载通过 `set_fan`、`set_pump`、`set_uv`、`set_anion` 记录实际输出。档位只用作输出档位展示，
没有实际转速模型。通用存储和六个诊断槽位沿用现有接口。

## 可维护性和交付边界

- 本工具只配置 APL，未增加任意 C 控制程序、第三方插件、自由 QML 项目或 MCU 外设代码生成。
- 导出完整 C 源码，通过宏裁剪参与编译的功能；不试图删改函数体或自动生成业务判断。
- 硬件移植模板与库源码分目录。升级提示保留应用侧移植文件，不扫描或覆盖用户工程。
- 固定 ZIP 路径由生成器提供，产品名只作为元数据；输出使用 QSaveFile，失败保留旧归档。
- 编译器路径是工具设置，不写入产品文件和 SDK，因此产品文件可在不同电脑间交换。
- 后续扩展参数要先在 APL 建立真实配置能力，再加入模型、UI、SDK 和预览测试；不要添加只影响模拟器的假配置。

## 测试

`apl_sdk_test` 使用生成后的包编译三个独立 C 程序（完整机型 / 仅净化 / 仅加湿），包含移植模板和示例文件，
运行时检查功能、默认档位与按键裁剪；同时构建并加载预览库，验证加载失败后原库仍可运行。
Qt 自检覆盖后台编译、连续原子保存、实际业务变化、草稿隔离、错误保留与恢复、接口拒绝及过期构建丢弃。现有核心、联动、存储、界面测试继续保留。
