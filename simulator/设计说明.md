# 设计说明

## 分工

| 文件 / 对象 | 职责 |
|---|---|
| AplPlatform | 持有一份 struct apl；注入硬件 ops、绑定按键、驱动 tick、发布显示与事件 |
| AplMemory | 简单的 4096 字节文件存储；不规定业务保存策略 |
| FrontendCatalog | 两份固定 APL 调试视图的列表 |
| WorkbenchWindow | 菜单、传感器、固定负载、诊断槽位和事件显示 |
| RoundPanel.qml / KeyBench.qml | 两份内置面板，读取 platform 属性并上报按键电平 |

C 库静态链接，所有运行状态通过正式 getter/setter 与 ops 交换。库实例不依赖 QML，面板切换只改变显示。

## 时间和回调

宿主每 10 ms 调用 apl_tick，再 publish/pull 更新显示。暂停停止自动时钟，单步推进一拍。现有按键边沿会分别推进一拍，因此暂停时仍可以操作短按；长按可通过 advance(count) 验证。

按键回调先记录手势，再执行宿主已绑定逻辑并记录结果。回调上下文指向 AplPlatform；硬件回调和调试方法在 Qt 线程中调用，不另起通用控制程序线程。

## 固定负载方法

- fanSet(rpm)：记录实际风机转速命令，0 表示停止，负值或无供电时忽略。
- humidifierSet(on)：记录实际加湿器开关。
- UV / 负离子：由 apl_core_ops 中的 uv_set、anion_set 回调更新。

这些是理想负载输出，不含惯性或测速模型。APL 已提供 fan_set / pump_set 输出 ops，目前 Qt 宿主尚未接入这两路；方法保留为接线点，程序不会自行根据业务档位补做控制。

## 存储方法

AplPlatform 提供：

```cpp
bool openMemory(const QString &path);
bool memoryRead(uint32_t offset, uint8_t *data, uint32_t length) const;
bool memoryWrite(uint32_t offset, const uint8_t *data, uint32_t length);
bool memoryErase();
```

访问越界、无供电或文件失败返回 false。读取失败不改变输出缓冲。相同内容不重复提交，文件写入用 QSaveFile 原子替换，失败保留旧内存和文件。

APL 已提供 memory_save、apl_core_memory_get / restore，目前 Qt 宿主尚未对接保存与恢复。接线时在回调里使用以上字节存储方法，并明确记录编码与版本；保存字段和时机由 APL 决定。

突然掉电不执行存储写入，不做末次保存。文件模型不模拟写入中断、擦写寿命或多进程并发。

## 调试槽位

```cpp
platform.displaySet(0, QStringLiteral("阶段"), QStringLiteral("运行"));
platform.displayClear(0);
```

槽位编号 0–5。同一编号覆盖更新，同值不追加变化事件。通过 displaySlots() 读取，frameChanged 通知界面。槽位与固定负载独立，重置与掉电保留最后填写的信息，退出进程后消失。

## 构建边界

Qt 的 rcc 将两个内置 QML 编进可执行文件。工程不再包含用户外设类型、项目 JSON、动态库加载、编译器设置或 MCP。修改控制程序直接修改工程内 APL 源码，再通过 CMake 构建。
