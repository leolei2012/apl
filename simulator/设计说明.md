# 设计说明

## 分工

| 文件 / 对象 | 职责 |
|---|---|
| AplPlatform | 持有一份 struct apl；注入硬件 ops、绑定 APL 联动、驱动 tick、读取显示与记录事件 |
| AplMemory | 简单的 4096 字节文件存储；不规定业务保存策略 |
| FrontendCatalog | 两份固定 APL 调试视图的列表 |
| WorkbenchWindow / StudioTheme | 四页工作区、统一浅色样式、传感器、负载、诊断与事件抽屉 |
| RoundPanel.qml / KeyBench.qml | 两份内置面板，读取 platform 属性并上报按键电平 |

默认 C 库静态链接作为初始预览；绑定本地源码后，AplSource 监听保存，SdkPreviewJob 后台构建 APL，AplRuntime 加载与 SDK 快照相同的 APL 库。所有运行状态通过正式 getter/setter 与 ops 交换。库实例不依赖 QML，面板切换只改变显示。产品流程详见[配置格式与生成设计](产品配置格式与生成设计.md)。

## 时间和回调

初始化后调用 apl_link_bind；宿主每 10 ms 调用 apl_tick，再 observe/pull 读取显示。APL 内部先推进主控、同步快照，再推进 HMI；按键命令引起的主控状态在下一拍反映到显示。暂停停止自动时钟，单步推进一拍。现有按键边沿会分别推进一拍，因此暂停时仍可以操作短按；长按可通过 advance(count) 验证。

APL HMI 通过可选 ops.key_event 通知已通过功能启用和童锁检查的单键短按 / 长按，宿主只记录手势，不再实现按键业务。随后 APL 自己执行联动命令和本地显示动作，宿主分别记录实际结果。ops 需要清零初始化；硬件回调和调试方法在 Qt 线程中调用。

宿主通过快照展示 `run_state`、`dry_left_s`、`purify_on`、`humidify_on`，运行状态变化单独记录事件，不再用二值 power 把风干显示成正常运行。净化/加湿启用能力与当前开关分开，实际负载输出仍由 ops 决定。

数码管内容、单位、亮度、状态图标、氛围灯以及水位灯亮度和颜色均来自 HMI getter。QML 不按档位推断图标亮灭，支持数字及 OF、CL 七段字形。仿真菜单的滤芯查询调用 apl_hmi_filter_query，不改变滤芯寿命。

## 固定负载方法

- fanSet(rpm)：记录实际风机转速命令，0 表示停止，负值或无供电时忽略。
- humidifierSet(on)：记录实际加湿器开关。
- UV / 负离子：由 apl_core_ops 中的 set_uv、set_anion 回调更新。

这些是理想负载输出，不含惯性或测速模型。set_fan / set_pump 已接入宿主：风机显示实际输出的开关和档位，加湿器显示泵输出。不会将档位换算成虚构 rpm；fanSet(rpm) 仍可用于宿主调试输入。

## 存储方法

AplPlatform 提供：

```cpp
bool openMemory(const QString &path);
bool memoryRead(uint32_t offset, uint8_t *data, uint32_t length) const;
bool memoryWrite(uint32_t offset, const uint8_t *data, uint32_t length);
bool memoryErase();
```

访问越界、无供电或文件失败返回 false。读取失败不改变输出缓冲。相同内容不重复提交，文件写入用 QSaveFile 原子替换，失败保留旧内存和文件。

APL 已提供 memory_save、apl_core_get_memory / restore，目前 Qt 宿主尚未对接保存与恢复。接线时在回调里使用以上字节存储方法，并明确记录编码与版本；保存字段和时机由 APL 决定。

突然掉电不执行存储写入，不做末次保存。文件模型不模拟写入中断、擦写寿命或多进程并发。

## 调试槽位

```cpp
platform.displaySet(0, QStringLiteral("阶段"), QStringLiteral("运行"));
platform.displayClear(0);
```

槽位编号 0–5。同一编号覆盖更新，同值不追加变化事件。通过 displaySlots() 读取，frameChanged 通知界面。槽位与固定负载独立，重置与掉电保留最后填写的信息，退出进程后消失。

## 构建边界

Qt 的 rcc 将两个内置 QML、APL 源码和移植模板编进可执行文件。产品配置只控制 APL 已有参数，预览只编译生成的 APL SDK；本机编译器路径可设置。没有通用用户外设类型、自由 QML 项目、第三方控制程序或 MCP。修改 APL 实现后保存，自动只构建 APL 模块并重载；公共接口改变需要同步重建宿主，详见[开发与热重载](APL开发与热重载.md)。
